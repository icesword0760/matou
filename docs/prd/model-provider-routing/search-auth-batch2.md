# 网页搜索分配与行内重登：第二批界面交付

本关修改界面接线和测试，停在审查点，未提交、合并、发布或安装。第一批后端与契约保持原样。所有演示账号、模型和 RPC 返回均为假数据，没有真实账号操作、浏览器 OAuth 或付费模型请求。

## 用户可以完成什么

- Haiku 后新增“网页搜索”第 4 行，复用三档的列宽、控件和模型选择规则。未指定时说明搜索使用当前档位供应商；不提供自动跟随主模型。
- 搜索与三档共用“保存分配”，只有搜索修改也能保存；未指定发送 `webSearch: null`，重开后保持未指定。未修改时不保存；恢复默认同时清除三档与搜索，仍需保存。
- API Key 缺失、目录明确移除模型、账号失效和供应商删除时保留原值并禁止保存；读取失败提示重试。无权威目录的自定义 API 可以手填模型 ID。
- 三档和搜索行的托管订阅账号失效时显示“重新登录”，包括沿用默认供应商的三档行。实时 `accounts` 优先，缺少实时详情时回退供应商摘要。
- 行内按钮打开现有登录流程；弹窗打开期间同账号按钮忙碌且禁用。成功并保存账号后行内错误消失，保留未保存的搜索选择；失败保留错误和草稿。登录与分配保存均不调用默认供应商切换。
- 隐私说明中英文明确搜索请求包含当前对话。保存继续只对新会话生效；当前会话不重启。

## 我自己做的决定

1. DSH（实际 `deepseek-flash / high`）两次均在请求服务阶段报 `TRANSPORT`，没有界面产物；按监督回答 #1 的一次性授权由主代理完成机械接线，不再重试 DSH，不启用 Antigravity，未改变设计。
2. 搜索与三档放在一个组件草稿中，共用原保存焦点策略；提交时拆回 `{ assignments, webSearch }`。恢复默认清除两者，防止界面默认与实际搜索目标不一致。
3. 既有账号通知返回的实时供应商摘要更新 `accounts` 缓存的账号部分，保留模型/额度数据；不用再读额度，也不加轮询。
4. 重登忙碌期间覆盖同账号的所有分配行，使用现有弹窗是否打开作为状态；沿用默认供应商的三档也可显示按钮，但不改变退出混合分配时的旧校验语义。
5. 按“不新增视觉产物”裁决，不另做 mockup 或截图；浏览器仅输出布局、焦点、滚动和请求 JSON。没有子代理设计决定需要保留。
