## 1. 背景与动机

### 1.1 问题陈述

开发者与智能体协作时，一个事项通常会快速分成多条工作线：主方案继续推进，旁路方案验证可行性，另一条会话运行测试，还有一条会话等待用户确认。传统终端只把这些会话平铺成窗口或标签，用户很快会遇到以下问题：

- 看得到多个终端，却看不出它们从哪段工作分出来、彼此是什么关系。
- 想探索新方案时，要么污染当前对话，要么重新向智能体解释全部背景。
- 多个会话共用同一目录时，文件修改容易相互影响；使用独立工作树时，又缺少统一的创建入口和归属提示。
- 一屏出现大量分栏后，每个终端过窄，重要输出难以阅读。
- 用户离开一段时间后，很难判断哪些会话仍在工作、哪些正在等自己、哪些已经结束或出错。
- 会话层级增多后，仅靠标签和窗口位置很难快速回到父会话、兄弟会话或下一层子会话。
- 同一事项可能包含多个相互独立的工作主题，全部挤在一张关系图里会让画布越来越混乱。

用户需要的不是更多分屏，而是一套能表达“工作从哪里来、现在进行到哪里、下一步该关注谁”的会话组织方式。

### 1.2 机会

Matou 可以把一个事项中的终端会话组织成多张独立画布。每张画布都是一张可持续演进的会话关系图：

- 父子关系表达“工作从哪个节点继续组织”；Fork 标记进一步表达“继承了哪个 Claude Code 上下文”。
- 兄弟关系表达“在同一层并行推进另一项工作”。
- 工作树选择表达“共享同一份文件”或“隔离代码修改”。
- 横向会话浏览解决日常并行操作，DAG 画布解决复杂关系导航。
- 统一状态让用户一眼知道谁在运行、谁在等输入、谁已出错。

这一形态把传统终端的窗口管理升级为面向智能体任务的工作组织，同时保留 Shell 用户熟悉的即时输入体验。

### 1.3 非目标

以下内容属于后续阶段：

- 从历史对话中的任意一条旧消息处分叉；首版仅从当前会话的最新状态创建子分支。
- 自动合并不同工作树中的代码修改，或自动解决代码冲突。
- 把一张画布中的节点拖到另一张画布，或让同一会话同时出现在多张画布。
- 跨事项、跨工作空间建立父子或兄弟关系。
- 多人实时共同编辑同一张 DAG 画布。
- 多智能体团队内部角色编排；团队会话只作为普通节点显示其整体状态。
- 纵向新增会话入口；首版只保留横向兄弟创建和标题行子分支创建。
- 自动清理用户的工作树和未提交修改；清理由工作树管理能力单独承接。
- 跨设备同步画布、会话关系和运行状态。

## 2. 目标

### 2.1 产品目标

1. 用户可以在一个事项下创建多张独立会话画布，分别承载不同工作主题。
2. 用户可以明确创建根级兄弟、普通兄弟和 AI 子分支，不混淆“并排显示”与“继承上下文”。
3. 用户创建 Claude Code Fork 时可以选择共享当前工作树，或使用新的独立工作树；普通 Shell 沿用当前工作空间目录和既有创建体验。
4. 用户在日常操作中最多同时查看四个横向会话，并能平滑浏览更多会话。
5. 用户可以通过父会话徽章、横向滑动和全局 DAG 快速定位任意相关会话。
6. 用户可以准确识别 Shell 与 Claude Code 的运行、待输入、空闲、错误、中断和停止状态。
7. 用户关闭应用再打开后，画布、关系、聚焦位置和已有终端输出保持连续；关闭前正在执行的工作不被重复执行。
8. 任意节点创建、恢复或运行失败时，影响限制在当前节点，父会话、兄弟会话和其他画布继续可用。

### 2.2 核心原则

- **关系与位置分开**：父子、兄弟关系表达工作来源；横向位置只表达当前浏览顺序。
- **父子关系表达组织来源**：普通父子边表示会话归属，Fork 边额外表示 Claude Code 上下文继承。
- **兄弟关系由共同父节点形成**：根级会话共享画布起点；其他同级会话共享一个会话父节点，Shell 与 Claude Code 可以互为兄弟。
- **节点身份与运行形态分开**：会话节点是稳定的关系载体，Shell 与 Claude Code 是当前运行形态；形态切换不重写父子关系、兄弟归属和已有工作记录。
- **新增能力由当前形态决定**：Shell 形态保留已有子节点并可横向创建 Shell 兄弟；形成有效 Claude Code 对话后，节点额外获得创建 Fork 子节点和 Fork 兄弟的能力。
- **仅 Fork 选择文件隔离**：普通 Shell 直接使用当前工作空间目录；Claude Code Fork 可在共享当前工作树与使用新工作树之间选择。
- **状态表达真实工作**：会话存活、当前工作状态和最近活动分别表达，避免把“终端开着”误写成“任务运行中”。
- **复杂度按需展开**：日常使用留在横向会话区，复杂关系通过 DAG 浮层查看。
- **手势可撤销、可预期**：普通横向滚动与右拉返回父会话分成两次独立手势。
- **关系结构优先保留**：停止运行不抹去其父子关系，后续仍能理解工作演进过程。
- **显式失败**：创建失败、恢复失败和工作树异常都有明确状态与恢复入口。

### 2.3 成功标准

- 新用户在首次使用时，可以在两分钟内完成“创建画布 → 创建会话 → 创建子分支 → 返回父会话”。
- 用户能仅凭节点位置、连线和标签准确说出父子、兄弟以及根级兄弟关系。
- 用户在看到“运行中”“待输入”“空闲”时，对会话真实情况的判断一致。
- 创建新会话后，键盘焦点自动进入新会话；Claude Code 完成本轮回答后，输入焦点仍可直接继续使用。
- 在五个以上兄弟会话中，用户能通过横向滑动找到目标，并且普通滑动不会直接触发返回父会话。
- 关闭应用再打开后，用户回到上次事项、画布和聚焦节点，DAG 关系保持一致。
- 新工作树创建失败、AI 分叉失败或单会话异常时，其他会话继续工作。
- 所有会话创建入口、关闭入口和状态徽章在白色与深色主题下含义一致。

## 4. 功能详述

### 4.1 功能清单

- **F1 — 多画布 Tab**：一个事项可以包含多张独立会话画布，顶部每个 Tab 对应一张画布。
- **F2 — 新画布默认 Shell**：新建画布时直接创建一个使用当前工作空间目录的 Shell，不展示会话类型或工作树选择。
- **F3 — 通用父子与兄弟关系**：每个会话拥有画布起点或会话父节点；共享父节点的 Shell 与 Claude Code 互为兄弟。
- **F4 — 横向新建 Shell**：在任意同级列表横向新建普通 Shell，新节点与当前会话共享父节点并追加到末尾。
- **F5 — Claude Code Fork 子分支**：从当前 Claude Code 的最新对话状态创建带 Fork 标记、继承上下文的独立子会话。
- **F6 — Fork 工作树选择**：创建 Claude Code 子分支或 Fork 层兄弟时，选择共享当前工作树，或在新工作树中创建。
- **F7 — 子会话数量与聚合状态**：父会话标题行显示直接子会话总数、当前 Claude Code / Shell 形态构成，以及需要关注的最高优先级状态；DAG 连线独立标记普通关系或 Fork 关系。
- **F8 — 同级会话横向浏览**：点击会话徽章后，以横向列表显示共享该父节点的全部直接子会话，一屏最多四个。
- **F9 — 悬浮扩展**：鼠标悬浮某个会话时，该会话自动扩展到更适合阅读的宽度。
- **F10 — 右拉返回父会话**：到达最左后，通过一次新的右拉手势拉出父会话投影并返回。
- **F11 — DAG 全局浮层**：长按 Option + Tab，在应用界面之外打开当前画布的会话关系浮层。
- **F12 — DAG 平滑画布**：支持平移、缩放、层级虚影、实时节点摘要和连线展示。
- **F13 — 节点选择与聚焦**：点击 DAG 节点后关闭浮层，切换到对应画布位置，确保目标会话完整进入视野并获得焦点。
- **F14 — 统一会话状态**：Shell 与 Claude Code 使用一致的用户可见状态语义，并保留各自不同的判断边界。
- **F15 — 停止不移除**：停止会话只改变运行状态，同一节点继续出现在横向列表与 DAG，子节点关系继续可读。
- **F16 — 关闭与恢复**：画布、会话关系、聚焦位置和已关闭画布可在重启后继续使用。
- **F17 — 创建失败恢复**：准备工作树、继承对话或启动会话失败时，提供重试和移除入口。
- **F18 — 会话列表动态排序**：同一层会话按最近一次真实用户交互倒序排列，最新交互的会话移动到最前。
- **F19 — Claude Code 运行绑定恢复**：恢复失败提供重试入口；手动退出后返回 Shell，原节点身份、已有输出和子节点关系保持。
- **F20 — DAG 通知映射**：横向会话卡片存在通知状态时，DAG 中的同一节点同步显示蓝色呼吸边框，直至该会话的通知状态被清除。

### 4.2 交互逻辑

#### 4.2.0 交互 Mockup

- [打开可交互 Mockup：会话画布与 DAG 分支交互](./mockups/Matou-会话画布与DAG分支交互.html)
- Mockup 用于说明多画布、默认 Shell、通用父子与兄弟关系、Claude Code Fork、恢复重试、横向浏览、动态排序、二次右拉返回以及 `Option + Tab` DAG 浮层。
- 本文中的行为断言、状态定义和验收标准为评审依据；Mockup 负责帮助理解交互形态。

#### 4.2.1 进入事项与画布

- **触发方式**：用户点击侧栏中的事项。
- **前置条件**：事项所属工作空间目录可用。
- **交互步骤**：
  1. 界面打开用户上次使用的画布。
  2. 恢复该画布上次聚焦的会话、横向位置和 DAG 观察位置。
  3. 当前会话自动获得键盘焦点。
- **完成状态**：用户可以直接继续输入，无需再次点击终端。
- **异常反馈**：工作空间目录失效时，保留画布和关系结构，创建与输入入口置灰，并提示用户恢复目录位置。

首次创建的默认事项包含一张默认画布和一个 Shell 会话。用户主动点击顶部 `+` 创建后续画布时，新画布同样以 Shell 作为首个根级会话。

#### 4.2.2 新建画布

- **触发方式**：点击顶部 Tab 栏的 `+`。
- **前置条件**：当前事项可用。
- **交互步骤**：
  1. 在当前 Tab 右侧新增一张画布并立即切换过去。
  2. 系统沿用当前工作空间目录，自动创建一个 Shell 根级会话。
  3. Shell 自动获得键盘焦点。
- **完成状态**：Shell 位于画布根层并自动获得焦点，用户可直接输入命令；在 Shell 中启动 Claude Code 后，会话标题和能力随实际模式变化。
- **异常反馈**：Shell 创建失败时保留新画布，显示失败原因和重新创建入口。

新画布初始名称使用“新画布”“新画布 2”等顺序名称。Shell 创建后，未被用户重命名的画布可根据 Shell 和工作目录生成更易识别的标题。用户手动命名后，标题保持固定。

#### 4.2.3 父子与兄弟关系

一张画布拥有一个只负责组织关系的“画布起点”。它不是终端会话，不显示运行状态，也不计入分支数量。

- 画布中的第一个会话以画布起点为父节点，属于画布根层。
- 每个非根级会话拥有一个会话父节点；共享同一父节点的会话互为兄弟。
- 兄弟列表可以同时包含 Shell 与 Claude Code，兄弟关系只表达同层组织，不表达对话继承。
- 普通父子边表达创建归属；带 Fork 标记的父子边额外表达 Claude Code 上下文继承。
- DAG 中用一个轻量起点和共同连线表示它们属于同一张画布。
- 用户想继承当前 Claude Code 上下文时，应使用“创建子分支”入口。

#### 4.2.4 横向创建兄弟会话

- **触发方式**：点击当前会话标题行的横向分栏图标。
- **前置条件**：画布和工作空间可用。
- **交互步骤**：
  1. 用户点击普通横向新增时，系统直接创建 Shell，不展示弹框。
  2. 新 Shell 与当前会话共享父节点；根层共享画布起点，其他层共享当前列表的会话父节点。
  3. 新会话追加到当前兄弟队列末尾。
  4. 横向列表自动滚动到新会话，新会话自动获得焦点。
- **完成状态**：新会话与当前会话同级。
- **异常反馈**：创建失败时在队列末尾显示失败卡片，提供“重试”和“移除”。

关系规则：

- 横向普通新增始终创建 Shell 兄弟，不继承任何会话的对话内容。
- 需要创建 Claude Code Fork 兄弟时，使用专门的“从共同父会话 Fork”入口，并选择当前工作树或新工作树。
- Fork 兄弟继承共同父会话的上下文，不复制当前兄弟节点后续产生的内容。
- Fork 兄弟创建成功后追加到当前兄弟队列末尾；当前子会话继续保持焦点与原有横向位置，新节点不会主动抢占视野。
- 新建会话默认以 Shell 开始。用户在其中启动 Claude Code 并形成有效对话后，该节点才获得创建子分支的能力。
- Shell 与 Claude Code 都可以作为任意父节点下的子节点，也可以互为兄弟。
- 当前模式为 Shell 的节点可能保留过去在 Claude Code 模式下形成的子节点；关系不会因模式切换而消失。

#### 4.2.5 创建 Claude Code 子分支

- **触发方式**：点击 Claude Code 会话标题行的分支图标。
- **前置条件**：当前会话已经完成至少一轮有效对话，并具备可继续的会话身份。
- **交互步骤**：
  1. 用户选择在当前工作树或新工作树中创建。
  2. 用户填写分支名称。
  3. 系统在当前会话下方关系层新增一个准备中的子节点。
  4. 子会话继承父会话截至点击时的对话理解。
  5. 子会话就绪后自动聚焦，父会话保持原样。
- **完成状态**：父会话的分支数量增加；子会话拥有独立的后续对话。
- **异常反馈**：失败节点显示具体阶段、失败原因、“重试”和“移除”；父会话内容、焦点位置和其他子分支保持原样。

入口规则：

- Shell 标题行显示横向创建兄弟 Shell 的入口；已有子节点时继续显示子会话数量和导航徽章。
- Shell 模式下隐藏新 Fork 入口；用户启动 Claude Code 并完成首轮有效对话后，Fork 子分支入口进入可用状态。
- 用户在 Shell 中启动 Claude Code 后，标题切换为 Claude Code；完成首轮有效对话后，子分支入口进入可用状态。
- 尚未形成有效对话的 Claude Code 会话显示置灰的分支图标，悬浮提示“完成首轮对话后可创建分支”。
- 团队中的队友会话不开放独立子分支入口。
- 首版仅从当前最新状态创建子分支。

#### 4.2.6 Claude Code Fork 的工作树选择

仅在创建 Claude Code Fork 子分支或 Fork 兄弟时提供两个选项。新建画布和普通横向 Shell 沿用既有逻辑，不出现工作树弹框。

| 选项 | 用户看到的说明 | 适用场景 |
|------|---------------|---------|
| 在当前工作树中创建 | 与当前会话共享目录和未提交修改 | 快速验证、共同读取同一份修改 |
| 在新工作树中创建 | 创建独立目录和分支，修改相互隔离 | 多功能并行开发、不同方案对比 |

新工作树规则：

- 新工作树以当前工作树最近一次提交为起点。
- 当前未提交修改继续留在原工作树；选择前显示这一影响。
- 用户填写的分支名称已存在时，输入框直接提示“分支名称已存在”，并保留用户已填写内容。
- 当前工作空间不是 Git 仓库时，“在新工作树中创建”置灰，并标注“需要 Git 仓库”。
- 准备期间节点显示“正在准备工作树”；完成后显示分支名称和独立工作树标记。
- 同一工作树被多个会话使用时，节点显示“共享工作树”标记，提醒用户文件修改彼此可见。
- 停止运行或移除节点后工作树继续保留；用户可在工作树管理入口中另行清理。

#### 4.2.7 父会话分支徽章

父会话拥有直接子节点时，标题行显示两个相邻徽章：

- 数量徽章：例如 `5 个分支`。
- 状态徽章：例如 `2 个运行中`、`1 个待输入`、`1 个异常`或`全部空闲`。

状态徽章按以下优先级显示最需要关注的情况：

`错误 → 待输入 → 运行中 → 已中断 → 空闲 → 已停止`

悬浮徽章时展示全部状态数量。分支数量包含运行与已停止的全部直接子节点；运行状态统计仅表达当前真实状态。产品不提供“历史会话”分类、隐藏历史开关或单独的历史列表。

#### 4.2.8 进入与浏览子会话

- **触发方式**：点击父会话的分支数量或状态徽章。
- **交互步骤**：
  1. 当前父会话投影切换为其全部直接子会话。
  2. 一屏最多等宽显示四个会话。
  3. 超过四个时，用户可通过鼠标、触摸板或底部滚动提示横向浏览。
  4. 当前聚焦会话带有清晰边框和焦点标记。
- **完成状态**：用户可在任意子会话中输入、查看状态或继续创建下一级子分支。

横向滚动只在当前兄弟列表内移动。到达列表边缘时，当前这一次滚动正常结束，不连带触发层级切换。

#### 4.2.9 悬浮扩展

- 当前激活会话始终保持 Mockup 约定的最大宽度，作为默认阅读主体；只有用户激活另一个会话时，原激活卡片才恢复基础宽度。
- 鼠标悬浮其他会话后，该会话也临时扩展到最大宽度；此时激活卡片与悬浮卡片同时保持最大宽度，超出视野的部分进入横向浏览区域。
- 鼠标直接划入另一张卡片时，只要指针仍在会话列表范围内，旧卡片在跨越卡片间距期间持续保持展开，并把悬浮状态直接交给新卡片；中间不复位列表宽度和横向视野，新卡片只执行一次宽度过渡。
- 扩展过程不覆盖其他会话，兄弟顺序保持原样。
- 悬浮只是临时预览，不写入会话列表的浏览位置；鼠标离开后直接恢复悬浮前的横向视野，只收起临时悬浮卡片，当前激活卡片全程保持最大宽度。连续划过多张卡片也不累计位移。
- 会话获得键盘焦点后以高亮边框持续标识；悬浮预览与激活状态可以同时扩展，但同一张卡片不叠加宽度。
- 窗口较窄时优先保证当前会话可读，其余会话缩为摘要卡片。
- 会话卡片不设置独立底栏；终端内容延伸至卡片底部，会话状态通过标题区、父级聚合徽章和 DAG 节点呈现。

#### 4.2.10 右拉返回父会话

- **触发方式**：兄弟列表已经停在最左侧后，用户结束当前滚动，再开始一次新的向右拖拽。
- **交互步骤**：
  1. 新手势开始后，左侧逐渐拉出父会话投影。
  2. 界面显示拉动进度和“松手返回父会话”提示。
  3. 未达到返回距离时松手，列表以弹力效果回到原位。
  4. 达到返回距离后松手，页面切回父会话并恢复其输入焦点。
- **异常避免**：从列表中部一次快速滑到最左只完成滚动；用户需再次向右拖拽才进入父会话投影。

会话列表不再占用独立的顶部层级栏。当前层级面包屑放在会话区域底部状态栏左侧，替换原“添加快捷指令”按钮；进入子层级后，该位置同时提供明确的“返回父会话”入口，服务于键盘操作、无触摸板环境和手势使用困难的用户。根层级仅显示“根会话 · N 个会话”，底部不再提供新增入口。

#### 4.2.11 打开 DAG 浮层

- **触发方式**：应用位于前台时，长按 `Option + Tab` 约半秒。
- **短按行为**：短按仍交给当前终端使用，Shell 的补全和 Claude Code 内部切换保持即时。
- **打开效果**：DAG 作为独立系统浮层出现，不受 Matou 客户端窗口边界裁切；默认显示在当前主窗口所在的显示器上。
- **默认范围**：以当前节点为中心，完整显示父层、当前层和子层三层关系。
- **更多层级**：三层以外的节点先以虚影提示方向；用户平移到对应区域后，节点逐渐变实并显示内容。
- **关闭方式**：按 `Esc`、点击关闭按钮，或选择一个节点。
- **按键释放**：浮层出现后释放 Option 与 Tab，浮层继续保留，方便用户使用鼠标和触摸板浏览。

#### 4.2.12 DAG 平移、缩放与节点选择

- 用户可用鼠标拖拽或触摸板在任意方向平滑移动画布。
- 用户可用触摸板捏合、鼠标滚轮组合操作或浮层按钮缩放。
- 浮层提供“缩小”“放大”“100%”“聚焦当前节点”操作。
- 缩放范围为 40% 至 200%，到达边界时给出轻微阻尼反馈。
- 每个节点卡片显示会话名称、类型、工作树或分支、当前状态、最近四行信息和最近活动时间。
- 节点最新信息在会话工作时持续刷新；画布位置保持稳定。
- 节点存在通知状态时，使用与横向会话卡片一致的蓝色呼吸边框；通知被处理、进入该会话或从通知中心清除后，DAG 边框同步消失。
- 父子节点通过有方向的连线连接；兄弟节点通过共同父节点自然呈现。
- 根级兄弟通过画布起点汇聚，不制造虚假的对话父会话。
- 点击节点后浮层消失，主界面切换并聚焦该节点。
- 目标节点有兄弟节点时，主界面先显示该兄弟列表，再自动滚动至目标会话完整进入可视范围；空间允许时居中显示，位于列表边缘时采用最小必要位移。
- 自动定位完成前保持目标会话的选中标记；悬浮扩展或窗口尺寸变化造成目标越界时，再次校正横向位置，保证目标会话持续可见。
- 目标节点是父节点时，主界面恢复父会话单节点视图。

#### 4.2.13 创建下一级子会话

子会话可以继续创建自己的子会话：

- 点击该 Claude Code 会话标题行的分支图标，创建它的直接子节点。
- 在父会话视图中创建的节点归属于该父会话。
- 任意层的普通横向新增都创建 Shell 兄弟；Claude Code 节点另有 Fork 子分支入口，Fork 兄弟使用“从共同父会话 Fork”入口。
- 向下创建窗口按钮从产品中移除，避免把“布局方向”误认为“关系方向”。

#### 4.2.14 停止运行、移除节点与关闭画布

**停止运行**：

- 用户在 Claude Code 内主动退出时，终端节点保持打开，当前模式切换为 Shell；这是正常用户操作，不显示“Claude Code 已停止”状态。
- 用户从卡片右上角“更多”菜单选择“停止运行”时，只停止当前进程，节点不消失。
- 正在运行或待输入的会话停止后进入“已停止”，已有输出、父子关系和兄弟关系保持不变。
- 已停止节点继续同时显示在横向会话列表与 DAG 中，可在原卡片重新启动。
- 父节点停止后，其子节点继续存在；父节点保留连线并可重新启动。
- 已停止节点使用“重新启动”原位恢复；Claude Code 恢复失败时回到 Shell 并保留重试恢复入口。

**移除节点**：

- 活跃卡片只保留“更多 → 移除节点…”入口；停止卡片、启动失败卡片、Fork 失败卡片和关闭快捷键进入同一确认流程，不再绕到旧的删除会话动作。
- 没有子节点的节点沿用最短确认路径；确认后同时从横向列表与 DAG 消失。
- 有后代的节点必须由用户选择“仅移除当前节点”或“移除当前节点及全部后代”，默认选择前者。
- 每个选择分别展示受影响会话数；可由当前投影确定时，同时展示受影响的自有 Worktree 数，并列出运行中、待输入影响。
- “仅移除当前节点”在同一事务中把直接子节点重连到当前节点的父级；当前节点为根时，直接子节点提升为根节点。选择完整分支时停止受影响进程并移除完整子树。
- 两种范围都不清理用户本地工作树；工作树和未提交修改继续保留。

**关闭画布**：

- 关闭非最后一张画布时，该画布进入事项的“已关闭画布”列表。
- 画布存在运行中或待输入会话时，先说明受影响会话数量；确认后结束这些会话并关闭画布。
- 关闭的画布保留节点关系、名称、摘要和工作树归属，可从事项菜单重新打开。
- 关闭当前事项的最后一张画布时，沿用事项关闭规则，避免产生没有工作入口的事项。
- 当前应用只剩最后一个事项和最后一张画布时，关闭窗口仅隐藏应用，现有会话继续保持；再次打开时回到原现场。

#### 4.2.15 重启与恢复

- 应用重新打开后，恢复工作空间、事项、画布 Tab、DAG 关系、节点名称、上次聚焦节点、横向位置和 DAG 缩放位置。
- 把会话拖到独立窗口、关闭独立窗口或返回主窗口，只改变展示位置；同一个会话和当前 Shell / Claude Code 形态保持不变。
- Shell 恢复到上次工作目录，并显示已有终端输出；关闭时尚未完成的命令标记为“已中断”，不自动重新执行。
- 上次关闭时处于 Claude Code 模式的节点尝试回到原对话；成功后进入空闲状态，失败后当前模式回到 Shell，并显示“Claude Code 恢复失败”和“重试恢复”按钮。
- 恢复失败分为两类：临时启动异常保留“重试恢复”；原 Claude Code 对话标识已失效或本地对话记录缺失时，节点回到 Shell 并明确说明原对话已失效，不继续展示重复重试入口。
- 用户主动退出 Claude Code 后，节点已经处于 Shell 模式；下次打开时按普通 Shell 恢复，不生成退出提示，也不触发 Claude Code 自动恢复。
- “重试恢复”进入统一的恢复中状态；成功后回到 Claude Code，失败后继续保留原因和重试入口。
- 恢复失败和手动退出都只改变当前运行模式；节点、父子关系、兄弟关系、已有子节点和分支徽章保持原样。
- 当前模式为 Shell 时，已有子节点仍可查看和进入；新 Fork 入口暂时隐藏，重新进入有效 Claude Code 模式后再次出现。
- 创建新工作树或子分支的过程中应用退出时，下次打开显示“创建已中断”，由用户选择重试或移除。
- 单个节点恢复失败时，其他节点和画布正常恢复。

#### 4.2.16 会话列表动态排序

根级会话列表与每个父会话下的直接子会话列表，都按“最近一次真实用户交互时间”倒序排列。排序只影响横向列表的浏览顺序，父子关系、兄弟归属和 DAG 中的稳定位置保持原样。

| 操作 | 是否更新会话交互时间 | 用户看到的结果 |
|------|:-------------------:|---------------|
| Shell 提交命令 | 是 | 记录最新交互；当前 Shell 保持原位，切换到其他卡片后再更新排序 |
| Shell 发送中断、结束输入等会影响当前进程的控制操作 | 是 | 记录最新交互；当前 Shell 保持原位，失去激活后再更新排序 |
| Claude Code 发送消息 | 是 | 记录最新交互；当前会话保持原位，失去激活后再更新排序 |
| Claude Code 完成授权、拒绝、选项或确认 | 是 | 记录最新交互；当前会话保持原位，失去激活后再更新排序 |
| Claude Code 主动停止或继续当前工作 | 是 | 记录最新交互；当前会话保持原位，失去激活后再更新排序 |
| 只输入文字但尚未提交 | 否 | 顺序保持原样，避免输入过程中反复跳动 |
| 点击、聚焦、滚动、缩放、复制、选择文本或查看 DAG | 否 | 顺序保持原样 |
| Shell 输出、Claude Code 回答、状态变化或通知到达 | 否 | 内容与状态更新，顺序保持原样 |
| 新建 Shell、创建 Fork 或重新启动已停止会话 | 否 | 新会话先追加在当前队列末尾 |

激活卡片的列表位置在整个连续操作期间锁定；用户可以连续输入、提交和等待回复，页面不因排序突然移动。当用户激活另一张卡片时，上一张卡片才按其最后一次真实交互更新排序，只发生一次平滑换位。多个会话交互时间一致时保持原有相对顺序。点击 DAG 节点仅负责定位目标会话，不会把该节点改成“最近交互”。

### 4.3 数据逻辑

#### 数据来源

- 画布关系来自用户创建根级会话和执行 Claude Code Fork 时形成的真实操作。
- Claude Code 子分支的初始理解来自父会话点击分支时的最新对话状态。
- 会话状态来自会话当前真实工作阶段，而不是屏幕上是否存在某段固定文字。
- DAG 节点摘要来自该会话最新输出；默认显示最近四行。
- 工作树标记来自会话实际使用的工作目录和分支。
- 会话列表顺序来自用户最近一次实际提交给各会话的操作；输入草稿、查看动作和后台活动不参与排序。

#### 数据刷新

- 会话开始工作、等待输入、完成、报错或退出后，对应节点、父会话徽章、画布 Tab 和事项摘要同步变化。
- 节点最新四行在输出产生时持续刷新，刷新期间不移动用户的画布视角。
- 用户向 Shell 提交命令或控制操作、向 Claude Code 发送消息或完成明确选择时，更新事项层面的“最近用户操作时间”。
- 会话列表的“最近交互时间”只在用户向 Shell 提交命令或控制操作、向 Claude Code 发送消息或完成明确选择时更新。
- 后台持续输出只更新节点内容和运行状态，工作空间、事项和画布的侧栏排序保持原样。
- 单纯点击、滚动、缩放和切换焦点时，最近用户操作排序保持原样。

#### 数据持久性

- 关闭应用后，事项下的画布、节点关系、名称、顺序、工作树归属、停止状态和上次焦点继续保留。
- 覆盖安装新版本后，上述内容继续保留。
- 关闭画布后，其内容进入“已关闭画布”，由用户主动恢复。
- 已停止节点继续保留在 DAG 中，直到用户执行符合规则的移除操作。
- 工作树与本地修改独立保留，停止会话或关闭画布不主动清理。

#### 数据归属

- 每张画布只属于一个事项。
- 每个会话节点只属于一张主画布。
- 父子关系只存在于同一张画布、同一个事项中；普通父子边表达会话归属，Fork 父子边额外表达 Claude Code 上下文继承。
- 非根级兄弟由共同父节点形成；根级兄弟由共同画布起点形成。同一兄弟列表可以混合 Shell 与 Claude Code 当前形态。
- 一张画布可以包含使用不同工作树的会话节点。
- 同一工作树可以被多个会话共享；界面需明确显示共享状态。

#### 数据隔离

- 切换画布只更新当前观察的关系图，其他画布中的会话状态保持原样。
- 新工作树中的修改与原工作树隔离。
- 当前工作树中的多个会话共享文件变化，用户在创建前和节点标记中都能看到这一事实。
- 一张画布发生创建或恢复失败，不影响同事项其他画布。

### 4.4 状态与反馈

#### 4.4.1 会话状态总表

| 状态 | 触发条件 | 视觉呈现 | 用户可进行的操作 |
|------|---------|---------|------------------|
| 启动中 | 新会话、恢复会话或新工作树正在准备 | 蓝色进度环；节点显示当前阶段 | 等待、取消创建 |
| 恢复中 | 正在恢复上次 Claude Code 对话 | 蓝色进度环；显示“正在恢复 Claude Code” | 等待、取消 |
| 空闲 | Shell 已出现提示符；Claude Code 已完成本轮并可接收新输入 | 灰色圆点；无呼吸动画 | 输入命令或消息；横向创建 Shell 兄弟；有效 Claude Code 创建 Fork 子分支 |
| 运行中 | Shell 命令正在执行；Claude Code 正在思考或使用工具 | 绿色圆点与轻微呼吸动画 | 查看输出、切换会话、停止当前工作 |
| 待输入 | 当前工作明确依赖用户输入、授权或选择 | 琥珀色铃铛；优先显示在父级徽章和画布 Tab | 切换到会话并完成输入 |
| 错误 | 当前命令、智能体工作、创建或恢复以错误结束 | 红色错误标记；显示简短原因 | 查看详情、重试、重新打开或结束 |
| Claude Code 恢复失败 | 预期恢复的原对话没有恢复成功 | 当前窗口回到 Shell；标题行显示红色恢复失败徽章 | 使用 Shell、查看已有子节点、重试恢复 |
| 已中断 | 用户主动停止，或应用退出时工作尚未完成 | 琥珀色中断标记 | 重试、继续可恢复对话、重新运行命令 |
| 已停止 | 会话进程已停止，节点继续保留 | 深灰空心圆；卡片降低强调度 | 查看已有输出、原位重新启动、移除节点或整个分支 |

“待输入”只用于明确阻塞在用户操作上的情况。Claude Code 正常回答完成后进入“空闲”；Shell 或 Claude Code 仅仅保持打开也属于“空闲”。

#### 4.4.2 Shell 状态流转

| 当前状态 | 用户或会话变化 | 下一状态 | 用户感知 |
|---------|---------------|---------|---------|
| 启动中 | Shell 已可输入 | 空闲 | 光标自动获得焦点 |
| 空闲 | 用户提交命令 | 运行中 | 标题与 DAG 节点转为绿色运行态 |
| 运行中 | 出现明确交互请求 | 待输入 | 显示琥珀色待输入提示 |
| 待输入 | 用户完成输入 | 运行中 | 继续显示输出 |
| 运行中 | 命令正常结束并回到提示符 | 空闲 | 状态恢复灰色，输入保持可用 |
| 运行中 | 命令以错误结束 | 错误 | 显示错误状态，Shell 仍可输入下一条命令 |
| 错误 | 用户提交下一条命令 | 运行中 | 新一轮工作覆盖旧的当前状态 |
| 任意活动状态 | 用户停止运行 | 已停止 | 节点留在横向列表与 DAG，可原位重新启动 |
| 运行中 | 应用完整退出 | 已中断 | 重启后不重复执行原命令 |

对普通 Shell 中难以明确识别的交互等待，界面保持“运行中”，避免产生错误的待输入提醒。

#### 4.4.3 Claude Code 状态流转

| 当前状态 | 用户或会话变化 | 下一状态 | 用户感知 |
|---------|---------------|---------|---------|
| 启动中 | 新会话或原对话已就绪 | 空闲 | 输入区自动聚焦 |
| 空闲 | 用户发送消息 | 运行中 | 节点显示智能体正在工作 |
| 运行中 | 出现权限、选择或明确提问 | 待输入 | 父级徽章和通知入口提示用户处理 |
| 待输入 | 用户完成选择或输入 | 运行中 | 智能体继续工作 |
| 运行中 | 本轮正常完成 | 空闲 | 回答保留，输入焦点继续可用 |
| 运行中 | 本轮异常结束 | 错误 | 显示错误原因和重试入口 |
| 错误 | 用户重试成功 | 运行中 | 继续本轮或开始新一轮 |
| 任意 Claude Code 状态 | 用户主动退出 Claude Code | Shell 空闲 | 标题切换为 Shell，不生成错误或退出提示；已有子节点保留 |
| 恢复中 | 原对话恢复成功 | 空闲 | 标题切回 Claude Code，Fork 入口重新出现 |
| 恢复中 | 原对话恢复失败 | Claude Code 恢复失败 | 当前窗口进入 Shell，显示失败原因和重试恢复按钮 |
| Claude Code 恢复失败 | 用户点击重试恢复 | 恢复中 | 保持节点、关系和已有子节点，显示恢复进度 |
| 任意活动状态 | 用户停止运行 | 已停止 | 节点留在横向列表与 DAG，可原位重新启动 |
| 运行中 | 应用完整退出 | 已中断 | 重启后尝试恢复对话，不重复提交旧消息 |

#### 4.4.4 活动、存活与排序

三个概念分别呈现：

- **工作状态**：当前是运行、待输入、空闲、错误、中断还是停止，用于徽章。
- **会话存活**：当前会话是否仍可继续输入，作为节点详情中的次要信息。
- **最近活动**：最近一次输入、输出或状态变化，用于节点时间和实时摘要。

工作空间、事项和画布的动态排序使用“最近用户操作时间”。后台输出不会让侧栏项目反复跳动。

#### 4.4.5 聚合状态

父会话、画布 Tab 和事项摘要使用同一优先级：

1. 任一会话错误：红色“异常”。
2. 没有错误且任一会话待输入：琥珀色“待输入”。
3. 没有以上状态且任一会话运行：绿色“运行中”。
4. 没有以上状态且任一会话已中断：琥珀色“已中断”。
5. 存在可用会话但都空闲：灰色“空闲”。
6. 全部会话停止：深灰色“已停止”。

聚合徽章只显示最高优先级状态；悬浮后展示各状态的完整数量。

## 5. 信息架构与视觉要求

### 5.1 信息层级

| 信息元素 | 优先级 | 展示要求 |
|---------|:-----:|---------|
| 当前会话名称与类型 | 必显 | 标题行始终可见 |
| 当前会话工作状态 | 必显 | 标题行、DAG 节点和父级聚合处一致 |
| 当前会话输入区域 | 必显 | 聚焦状态清晰，创建与回答完成后保持可输入 |
| 分支数量 | 必显 | 有直接子节点时显示 |
| 最高优先级分支状态 | 必显 | 与分支数量相邻展示 |
| 当前工作树 / 分支 | 次要 | 标题行可折叠，DAG 节点显示简写 |
| “共享工作树”标记 | 必显 | 多会话共享时持续可见 |
| 最近四行信息 | 次要 | DAG 节点中显示；空间不足时减少行数 |
| 最近活动时间 | 次要 | DAG 节点和悬浮详情显示 |
| 完整状态分布 | 可折叠 | 悬浮聚合徽章时展示 |
| 更远层级节点 | 可隐藏 | 默认以虚影表示，平移后展开 |
| 已停止已停止节点 | 可折叠 | DAG 中低强调展示，可按状态筛选 |

### 5.2 空间让位规则

- 一屏最多同时完整展示四个兄弟会话。
- 窗口变窄时，优先保留当前聚焦会话、状态和输入区域。
- 非聚焦兄弟会话依次收敛为标题、状态和最新一行摘要。
- 分支数量与“待输入 / 错误”优先于工作树路径展示。
- 工作树路径过长时保留目录名和分支名，完整路径放入悬浮详情。
- DAG 节点缩小时优先保留名称、状态和连线，隐藏最新输出与时间。
- 节点数量较多时，默认只完整呈现三层，更远层级使用虚影与方向提示。
- 标题行空间不足时，创建入口收拢到会话操作菜单，但分支数量与状态徽章继续保留。

### 5.3 视觉语义约定

- 绿色：当前正在运行。
- 琥珀色铃铛：等待用户输入或授权。
- 红色：错误或异常结束。
- 灰色：空闲。
- 琥珀色中断标记：工作被中断，可由用户决定下一步。
- 深灰空心圆：会话已停止，节点与已有输出继续保留。
- 蓝色进度环：正在创建、准备工作树或恢复。
- 实线有方向连线：真实父子关系。
- 共同汇聚线：根级兄弟属于同一画布起点。
- 虚影节点：关系存在但当前超出默认三层范围。
- 当前聚焦节点使用最强边框与轻微放大；兄弟节点保持同层对齐。
- 父会话右拉投影使用弹性位移和逐渐增强的清晰度，达到返回距离后再显示确认文案。
- 白色与深色主题使用相同的状态颜色含义，并保持足够的文字与边界区分度。

## 6. 用户可感知的行为清单

1. 用户进入事项时，会回到上次使用的画布和会话，键盘可直接输入。
2. 默认事项首次出现时包含一张默认画布和一个 Shell 会话。
3. 用户点击顶部 `+`，系统会直接创建使用当前工作空间目录的默认 Shell，并自动聚焦，不出现额外弹框。
4. 新建过程中不要求用户选择 Shell 或 Claude Code；普通新建一律从 Shell 开始。
5. 每张画布拥有独立的 DAG、横向位置、缩放位置和聚焦节点。
6. 用户在任意同级列表普通横向新建时，系统直接创建 Shell；新节点与当前会话共享父节点，追加到末尾并自动聚焦。
7. 同一父节点下的 Shell 与 Claude Code 可以互为兄弟；兄弟关系不代表对话继承。
8. 用户使用“从共同父会话 Fork”入口时，新 Claude Code 节点与当前节点共享父节点，并继承共同父会话的上下文。
9. Shell 标题行提供横向新建兄弟 Shell 的入口；已有子节点时继续显示子会话数量和导航徽章。
10. 用户在同级会话列表点击“新建 Shell”时，新 Shell 直接加入当前列表，与列表内会话共享父节点。
11. Claude Code 完成首轮有效对话前，子分支图标置灰并说明启用条件。
12. Claude Code 完成首轮有效对话后，可以从标题行创建子分支。
13. 子分支继承父会话截至创建时的理解，创建后的对话彼此独立。
14. 子分支创建成功后自动聚焦；父会话的内容与滚动位置保持原样。
14.1 从子会话创建共同父会话的 Fork 兄弟时，当前子会话的位置和焦点保持不变，新 Fork 节点追加到当前兄弟队列末尾。
15. 只有创建 Claude Code Fork 子分支或 Fork 兄弟时，用户才会看到“当前工作树”和“新工作树”两个选项；创建 Shell 时没有这一步。
16. 非 Git 工作空间中，新工作树选项置灰并标明所需条件。
17. 当前工作树存在未提交修改时，选择新工作树前会看到“新工作树从最近提交开始”的提示。
18. 多个会话共享工作树时，每个相关节点显示“共享工作树”。
19. 新工作树准备失败时，失败只影响新节点，原会话和其他节点继续可用。
20. 父会话有子节点后，标题行显示子会话总数、Claude Code / Shell 当前形态构成和聚合状态；DAG 连线单独区分普通关系与 Fork 关系。
21. 分支聚合状态优先显示错误，其次待输入，再其次运行中。
22. 用户悬浮聚合徽章时，可以看到运行中、待输入、空闲、错误、中断和停止的完整数量。
23. 用户点击分支徽章后，父会话被其直接子会话列表替换。
24. 一屏最多完整显示四个兄弟会话，更多会话可横向滑动查看。
25. 当前激活会话始终保持最大宽度；鼠标悬浮其他会话时，悬浮卡片也临时保持最大宽度；连续划入另一张卡片时直接交接临时悬浮状态，新卡片只变化一次；离开后恢复悬浮前的横向视野并只收起悬浮卡片，连续划过卡片不改变列表位置，卡片内不显示独立底栏。
26. 普通横向滑动只移动兄弟列表，不直接返回父会话。
27. 用户滑到最左并结束当前手势后，再次右拉才会拉出父会话投影。
28. 右拉距离不足时松手，界面弹回子会话列表。
29. 右拉达到返回距离后松手，界面切回父会话并恢复输入焦点。
30. 用户也可以通过会话区域底部左侧的层级面包屑返回父会话；会话列表顶部不显示独立层级栏，底部原添加按钮同步移除。
31. 用户长按 `Option + Tab` 约半秒，会看到独立于应用窗口边界的 DAG 浮层。
32. 普通短按 Tab 保持终端原有的即时响应。
33. DAG 默认以当前节点为中心，显示父层、当前层和子层。
34. 更远层级以虚影显示；用户平移过去后节点变实并显示摘要。
35. 用户可以平滑移动 DAG，并在 40% 至 200% 之间缩放。
36. DAG 节点显示名称、类型、分支或工作树、状态、最近四行信息和最近活动时间。
37. 节点最新信息更新时，用户当前画布位置保持稳定。
38. 用户点击 DAG 节点后，浮层关闭，主界面聚焦该会话并确保整张会话卡片位于视野内。
39. 目标节点有兄弟时，主界面显示兄弟列表；空间允许时把目标节点置于视野中心，边缘场景采用最小必要滚动并持续保持可见。
40. 子会话可以继续 Fork 自己的子分支，形成更深层级。
41. 任意层普通横向创建都追加 Shell 兄弟；有效 Claude Code 的专属入口可从当前节点创建 Fork 子节点，或从共同父节点创建 Fork 兄弟。
42. Shell 回到提示符时显示空闲，而不是运行中。
43. Claude Code 正常完成回答后显示空闲；明确等待授权或选择时显示待输入。
44. 终端保持打开但没有当前工作时，不计为运行中。
45. 后台输出会更新节点状态和摘要，侧栏排序保持原样。
46. 单纯点击、滚动和缩放时，工作空间、事项和画布的动态顺序保持原样。
47. 新建会话后，键盘焦点自动进入新会话。
48. Claude Code 完成本轮回答后，输入区域继续可直接使用。
49. 用户停止有子节点的父会话后，同一个父节点继续显示在横向列表与 DAG，子节点继续可用。
50. 任意叶子节点沿用最短确认路径；带有后代的节点让用户明确选择仅当前节点或当前及全部后代。
51. 每个移除范围分别展示受影响会话数；投影可确定时展示自有 Worktree 数，并展示运行中与待输入数量。仅当前节点时直接子节点重连祖父或提升为根。
52. 停止会话或关闭画布后，本地工作树和未提交修改继续保留。
53. 关闭非最后一张画布后，可以从事项的“已关闭画布”重新打开。
54. 关闭含有运行中或待输入会话的画布前，用户会看到受影响数量。
55. 当前应用只剩最后一个事项和最后一张画布时，关闭窗口会隐藏应用并保持现场。
56. 应用重新打开后，画布、关系、名称、焦点和观察位置继续保留。
57. 关闭时仍在运行的 Shell 命令标记为已中断，重新打开后不自动重复执行。
58. Claude Code 恢复失败时，当前节点显示错误和重试入口，其他节点照常恢复。
59. 创建子分支过程中应用退出时，下次打开显示创建已中断，由用户决定重试或移除。
60. 已停止节点仍计入分支数量，并单独计入“已停止”，不计入“运行中”。
61. 独立窗口中的会话仍归属于原画布；DAG 可显示其位置并把对应窗口带到前台。
62. 同一会话列表中，激活卡片产生真实交互时保持原位；切换到其他卡片后，上一张卡片再按最近交互平滑更新排序。
63. Shell 提交命令或控制操作、Claude Code 发送消息或完成授权和选择，都属于真实用户交互。
64. 只输入尚未提交的文字、点击、聚焦、滚动、复制和查看 DAG 时，列表顺序保持原样。
65. 后台终端输出、Claude Code 回答、状态变化和通知到达时，列表顺序保持原样。
66. 新建或恢复的会话先位于队列末尾，首次真实用户交互后再参与动态排序。
67. 上一张卡片失去激活后再更新排序；新激活卡片继续保持焦点并完整位于视野内，DAG 的关系和稳定布局保持原样。
68. 用户主动退出 Claude Code 后，当前节点切换为 Shell，不显示停止状态，已有子节点和关系保持原样。
69. 当前模式为 Shell 的节点可以保留过去形成的子节点，并继续通过徽章或 DAG 进入这些子节点。
70. Shell 模式隐藏新 Fork 入口；重新进入有效 Claude Code 模式后，Fork 入口再次出现。
71. 应用恢复原 Claude Code 对话失败时，当前节点进入 Shell，并显示“Claude Code 恢复失败”和“重试恢复”按钮。
72. 用户点击“重试恢复”后看到恢复进度；成功回到 Claude Code，失败继续显示原因和重试入口。
73. 恢复失败不会改变节点、父子关系、兄弟关系、已有子节点或列表归属。
74. Shell 与 Claude Code 都可能拥有子节点和兄弟节点；当前模式只影响可用操作，不重写历史关系。

## 7. 边界与异常

### 7.1 边界场景

- **首次使用**：自动提供默认画布和 Shell，用户可以立即输入。
- **新画布的 Shell 创建失败**：画布继续保留失败说明和重新创建入口；其他画布保持原样。
- **多个根级会话**：全部通过画布起点组织，不产生虚假的对话父节点。
- **只有一个节点**：DAG 仍可打开，当前节点居中，父层和子层为空。
- **超过四个兄弟会话**：保持四个可读宽度，通过横向滚动访问其余节点。
- **超过三层关系**：默认三层完整显示，其余层使用虚影并按需展开。
- **大型画布**：一张画布包含 100 个节点时，仍可平移、缩放、搜索和选择；默认只完整呈现视野附近节点。
- **多个会话同时输出**：摘要分别更新，焦点、滚动位置和侧栏顺序保持稳定。
- **父会话已停止、子会话仍运行**：父节点以已停止样式保留，连线与子节点状态持续可见。
- **Fork 兄弟使用不同工作树**：每个节点显示自己的工作树或分支，不按父节点覆盖。
- **多个会话共享工作树**：所有相关节点显示共享提示。
- **工作空间目录改名或移动**：画布和关系继续保留，输入与创建入口进入受限状态；用户恢复目录后继续使用。
- **独立窗口**：节点关系仍归属于原画布；选择该节点时优先把独立窗口带到前台。
- **多显示器**：DAG 浮层出现在当前主窗口所在显示器，一次只显示一个浮层。
- **白色与深色主题**：状态、选中、悬浮和已停止节点保持清楚区分。
- **键盘操作**：Option + Tab 打开 DAG，Esc 关闭；方向键与明确返回入口覆盖核心导航。

### 7.2 异常场景

| 场景 | 用户感知 | 恢复路径 |
|------|---------|---------|
| Claude Code 尚未形成有效对话 | 分支图标置灰并说明“完成首轮对话后可创建分支” | 完成一轮对话后再次创建 |
| 父会话身份在创建期间失效 | 新节点显示“父会话已失效”，父会话和其他节点保持原样 | 返回父会话继续，或创建新的空会话 |
| 新工作树准备失败 | 新节点显示失败阶段和原因 | 重试、切换为当前工作树、移除失败节点 |
| 分支名称已存在 | 输入框就地提示并保留内容 | 修改名称后继续 |
| 工作空间不是 Git 仓库 | 新工作树选项置灰 | 使用当前工作树创建 |
| 工作空间目录失效 | 画布关系和 DAG 可查看，输入与创建入口置灰 | 恢复原目录位置后继续 |
| 新会话启动失败 | 当前节点显示错误，其他会话继续工作 | 重试、重新创建或移除节点 |
| 单个会话恢复失败 | 当前节点显示恢复错误 | 重试恢复；当前节点、已有输出与关系保持不变 |
| 应用在创建过程中退出 | 节点显示“创建已中断” | 重试或移除 |
| 应用在 Shell 命令运行时退出 | 节点标记“已中断” | 用户重新运行所需命令 |
| 画布含运行中会话时关闭 | 确认框列出受影响数量 | 取消关闭，或确认结束并归档画布 |
| DAG 内容暂时刷新失败 | 节点保留最后一次摘要并显示“信息稍后更新” | 会话恢复输出后自动更新 |
| DAG 节点数量过多 | 远处节点以简化卡片或虚影显示 | 缩放、平移、聚焦当前节点或搜索 |
| 右拉距离不足 | 父会话投影弹回 | 再次右拉或使用返回入口 |
| 目标独立窗口已经关闭 | 主界面显示已停止节点 | 继续可恢复会话或重新打开 Shell |

### 7.3 降级原则

- DAG 浮层暂时异常时，横向会话浏览、分支徽章和明确返回入口继续工作。
- Claude Code Fork 的新工作树能力受限时，当前工作树选项继续可用，并清楚标注共享影响；Shell 创建流程保持原样。
- Claude Code 子分支受限时，原会话、根级独立会话创建和新画布继续可用。
- 单个会话状态暂时不确定时，显示“状态更新中”，不猜测为运行中或待输入。
- 节点摘要暂时缺失时，仍显示名称、关系、工作树和最后确认状态。
- 单张画布恢复异常时，其他画布与事项继续可用。
- 手势体验受限时，明确按钮和键盘入口覆盖相同的核心导航。

## 8. 与其他模块的关系

- **工作空间与事项管理**：本模块获得当前工作空间、事项和目录可用状态；向事项提供画布数量、运行状态和最近用户操作时间。
- **会话恢复**：本模块提供画布归属和关系数据；恢复能力负责让 Shell 回到目录、让 Claude Code 回到原对话，并反馈恢复结果。
- **通知系统**：当会话进入待输入或错误状态时，本模块提供会话、画布和事项归属；通知系统负责提醒和点击跳转。
- **终端快捷键**：普通 Tab 保持终端行为；长按 Option + Tab 由本模块用于打开 DAG。
- **工作树管理**：本模块仅在 Claude Code Fork 时让用户选择共享或新工作树，并展示工作树归属；工作树管理负责后续保留、查看和清理体验。
- **独立窗口**：会话离开主窗口后仍归属于原画布；本模块在 DAG 中保留节点位置，并支持把独立窗口带到前台。
- **主题与视觉系统**：本模块沿用全局白色和深色主题，并提供统一的状态颜色、选中与悬浮语义。
- **事项排序**：本模块只在用户向会话完成真实提交或控制操作时提供最近用户操作时间；新建、点击、查看和后台输出不触发侧栏重排。
- **后续产物与检查页面**：会话节点提供稳定归属，使产物、代码修改和检查结果可以回到产生它们的会话和画布。

### 9.2 质量门槛

- **可用性**：关键关系操作同时具备视觉入口和非手势入口；用户不依赖隐藏手势完成核心工作。
- **响应感知**：点击会话、切换画布和 DAG 节点聚焦应即时反馈；长任务显示明确准备状态。
- **状态准确性**：空闲、运行中、待输入、错误、中断和停止互不混用；聚合状态与子节点一致。
- **关系一致性**：每个子节点只有一个直接父节点；普通边表达归属，Fork 边表达归属与上下文继承；运行形态变化不重写关系。
- **焦点可靠性**：新建、切换、返回父会话和 Claude 回答完成后，目标输入区域保持可直接使用。
- **失败隔离**：单节点、单工作树或单画布失败不扩散到其他工作。
- **视觉一致性**：白色与深色主题下，画布、节点、连线、选中和状态使用一致语义。
- **跨窗口一致性**：独立窗口节点与主窗口 DAG 的关系、状态和跳转结果一致。
- **数据连续性**：正常关闭、窗口隐藏、异常退出和覆盖升级后，关系与用户已确认的工作现场保持可理解。

| 创建过程中应用退出留下半完成节点 | 中 | 中 | 重启后标记创建已中断，提供重试和移除 |
| 多张画布中的默认 Shell 共享同一工作空间目录，用户误以为文件相互隔离 | 中 | 高 | 所有相关节点显示共享目录标记；需要隔离代码修改时，引导用户在 Claude Code Fork 中选择新工作树 |
| 会话在用户输入时突然换位造成操作中断 | 中 | 高 | 激活期间锁定卡片位置；只在切换到其他卡片后提交上一张卡片的最新排序 |

当前版本已确认的关键决策：

- DAG 快捷键采用长按 `Option + Tab`，普通 Tab 保持终端即时响应。
- 顶部 `+` 创建新画布并立即生成默认 Shell，沿用当前工作空间目录，不展示创建弹框。
- 会话节点是稳定的关系载体；Shell 与 Claude Code 是节点当前运行形态，形态变化时节点身份与关系保持原样。
- 任意同级列表的普通横向入口都创建 Shell 兄弟并追加到队尾；Fork 子节点和 Fork 兄弟使用 Claude Code 专属入口；向下创建窗口入口移除。
- 根级兄弟共享画布起点，不虚构真实会话父节点。
- 只有具备有效对话上下文的 Claude Code 会话可以创建子分支。
- 普通新建会话默认是 Shell；用户在其中启动 Claude Code 并形成有效对话后，该节点获得 Fork 能力。
- Shell 与 Claude Code 均可出现在任意层级并互为兄弟；当前为 Shell 的节点也可保留过去形成的子节点。
- 普通兄弟与 Fork 兄弟都由共同父节点体现；根级兄弟由共同画布起点体现。只有 Fork 边表示上下文继承。
- 用户主动退出 Claude Code 后直接回到 Shell，不展示停止状态；自动恢复异常才展示“Claude Code 恢复失败”和重试入口。
- 工作状态、会话存活和最近活动分别表达。
- 会话列表按最近真实用户交互动态排序；新会话先在末尾，点击、查看和后台输出不触发换序。

### C. 术语表

- **事项**：工作空间下的一项具体工作，可包含多张会话画布。
- **画布**：事项下的一张独立会话关系图，对应顶部一个 Tab。
- **画布起点**：用于组织根级兄弟的轻量起点，不承载终端或对话。
- **会话节点**：画布中的稳定终端会话身份；其当前运行形态可以在 Shell 与 Claude Code 之间切换。
- **当前运行形态**：节点此刻呈现为 Shell 或 Claude Code，决定当前可用入口，节点关系保持原样。
- **父节点**：当前节点在画布关系中的直接来源；可以是画布起点或另一个会话节点。
- **子节点**：以某个会话为父节点创建的会话；可以是普通归属，也可以是带上下文继承的 Fork。
- **Fork 子分支**：从有效 Claude Code 父会话最新状态 Fork 出来的独立新会话。
- **Fork 兄弟**：分别从同一个真实父会话 Fork 出来、位于同一层的多个子会话。
- **兄弟节点**：共享同一父节点的会话，可混合 Shell 与 Claude Code 当前运行形态。
- **根级兄弟**：共享画布起点、没有真实会话父节点的独立会话。
- **当前工作树**：与当前会话共享文件和未提交修改的工作目录。
- **新工作树**：从最近提交创建的独立目录和分支，用于隔离修改。
- **DAG 浮层**：独立于应用窗口边界显示的会话关系总览，可平移、缩放和选择节点。
- **工作状态**：会话当前处于启动、空闲、运行、待输入、错误、中断或停止中的哪一种情况。
- **Claude Code 恢复失败**：应用预期恢复原 Claude Code 对话但未成功；节点暂时呈现 Shell，并提供重试恢复。
- **已停止**：当前终端进程已经停止，但会话节点、已有输出和关系仍保留在横向列表与 DAG 中；用户只退出 Claude Code 回到 Shell 时不进入该状态。
- **最近活动**：会话最近一次输入、输出或状态变化。
- **最近用户操作**：用户最近一次向 Shell 或 Claude Code 完成真实提交或控制操作，用于工作空间、事项和画布排序。
