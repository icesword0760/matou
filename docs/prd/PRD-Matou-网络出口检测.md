# PRD：网络出口检测与出口保护

| 字段 | 值 |
|---|---|
| 日期 | 2026-11-13 |
| 状态 | 待确认 |
| 范围 | 检测 Matou 里 agent 会话的真实网络出口；出口异常时提醒、拦截新会话、冻结运行中的官方 agent 会话，网络恢复后自动继续；官方 agent 会话使用非大陆的东八区时区 |
| 代理策略 | Matou 不内置代理（用户 2026-11-13 决定），网络由用户自己的 Clash 等工具负责，推荐开 TUN；Matou 负责检测、止损和时区处理 |
| 不在范围 | 内置代理 / 订阅导入 / 节点选择；Matou 自己开 TUN；虚拟机隔离；修改系统时区；多账号各绑节点；DNS 泄露检测 |
| 参考 | 开源项目 Cage（MIT）的「网络与隔离检查」与「出口规则」，本期取其主机侧可用部分 |

## 1. 产品结论

国内用户在 Matou 里使用 Claude Code、Codex、Antigravity 时，最怕在不知情的情况下用大陆 IP 或跳变的 IP 访问官方服务，进而导致封号。Matou 不接管代理，而是持续检测 agent 实际会用的网络出口，并去掉 agent 环境里的大陆时区：

- 每张官方 agent 卡片的 HUD 显示出口状态，点开查看逐项检查结果和修复建议。
- 出口被确认在中国大陆，或违反出口规则（比如 IP 跳到别的国家）时，Matou 立刻冻结所有正在运行的官方 agent 会话，并拦住新会话。冻结时任务停在原处、不丢失；网络恢复后自动继续。
- 检测服务超时、结果不确定时只提醒，不冻结，避免误伤正在进行的工作。
- 官方 agent 会话启动时，时区从大陆时区换成同为东八区的新加坡（出口在台湾时用台北）。时钟读数和北京时间完全一样，用户不会察觉任何时间差，服务商也看不到 `Asia/Shanghai`。语言保持用户原设置不变。Shell 卡片和系统本身不受影响。

reference product 没有此能力，本期不适用 1:1 对照矩阵，按本 PRD 场景表验收。

## 2. 用户场景

- 用户开着 Clash 规则模式，以为都走了代理，实际 `api.anthropic.com` 被分流成了直连。Matou 在启动会话前发现这一点，直接拦下。
- 用户只开了 Clash 的「系统代理」，没有开 TUN，也没设 `HTTPS_PROXY`。浏览器能正常访问 Claude，但终端里的 agent 全部走直连（CLI 不读 macOS 系统代理）。Matou 指出原因和修复办法。
- 会话跑到一半，机场节点挂了，Clash 自动切到别的地区，或者回落到直连。Matou 在一分钟内发现，冻结 agent，等用户修好网络再继续。
- 海外用户、或使用国内第三方服务商（DeepSeek、Kimi 等）驱动 Claude Code 的用户，不受影响。

## 3. 目标 / 非目标 / 反目标

- **目标：** 让用户随时知道「官方服务看到我是哪个 IP、在哪个国家」；出口确认异常时，agent 不再继续发请求。
- **非目标：** 不替用户修网络，不内置代理，也不保证每一条连接都走同一出口（只能周期采样）；不改系统时区。
- **反目标（做到了也算失败）：**
  - 误冻结频繁打断正常工作：检测超时、地理库误判时，不能冻结或必须一键可越过。
  - 给不需要的人添负担：海外用户和第三方服务商会话，不能多出任何提示或步骤。
  - 检测本身拖慢 Matou：启动、开卡片不能因为检测而等待。

## 4. 方案取舍

| 方案 | 用户价值 | 代价 | 结论 |
|---|---|---|---|
| A. 内置代理核心（打包 mihomo） | 固定出口 | 中等：订阅、节点界面、三平台打包；与用户 Clash TUN 叠加会变成双层代理 | 不做（用户决定）。用户自己的 Clash TUN 防漏更彻底，节点跳变和分流错误由本期检测兜底 |
| A2. Matou 自己开 TUN | 全局接管 | 与用户 Clash 的 TUN 抢路由和 DNS，需要管理员权限 | 不做 |
| B. 连接外部隔离环境（Cage 虚拟机 / VPS） | 隔离最彻底 | 大：HUD、恢复、分叉都依赖本机会话文件，要重做 | 以后视需求 |
| C. 内置虚拟机 | 同 B | 最大，镜像几十 GB、启动要等 | 不做 |
| **本期：检测 + 出口保护 + 时区处理** | 风险可见、可止损，不暴露大陆时区 | 小，复用现有暂停能力；时区只是会话环境变量 | **做（用户 2026-11-13 确认）** |

出口异常时的处理，用户在三档中选了最强的一档：提醒 + 拦新会话 + 冻结运行中的会话。

## 5. 功能规格

### 5.1 出口状态标签

Matou 没有全局底部状态栏，出口状态显示在每张官方 agent 卡片底部的 HUD 里，位于账户标签左侧，显示该卡片所属服务商的出口。Shell 卡片和第三方服务商卡片不显示。点击打开「网络检查」面板。

| 状态 | 显示 | 触发 |
|---|---|---|
| 检查中 | `出口检查中…`（灰） | 首次检查尚未返回。不阻塞任何操作 |
| 正常 | `🇺🇸 美国 · 出口正常`（默认色） | 所有关键检查通过 |
| 提醒 | `🇺🇸 美国 · 1 项提醒`（黄） | 关键检查都通过，但有提醒项（如时区不符），或最近一次检测超时 |
| 异常 | `出口异常 · 已暂停 3 个会话`（红） | 任一关键检查确认失败 |
| 已越过 | `出口异常 · 已手动继续`（红，描边） | 用户在异常状态下选择「仍要继续」 |

### 5.2 检查项

**关键检查**（失败即进入「异常」并冻结）：

| # | 检查项 | 怎么判断 | 失败时的修复建议 |
|---|---|---|---|
| K1 | 出口不在中国大陆 | 通过 agent 的网络路径访问各服务商的 Cloudflare `/cdn-cgi/trace`，读取 `loc`，`loc=CN` 即失败（香港、澳门、台湾不计入大陆） | 检查代理是否开启；规则模式下确认服务商域名走代理 |
| K2 | 出口符合出口规则 | 每个服务商的 API 出口（`api.anthropic.com`、`api.openai.com`）分别与它自己的出口基准对比，见 5.4 | 确认节点；IP 是预期变化时，在面板里「以当前出口为准」 |

**提醒项**（只变黄，不冻结）：

| # | 检查项 | 怎么判断 |
|---|---|---|
| W0 | 同一服务商的登录与 API 同一出口 | `claude.ai` 与 `api.anthropic.com`、`chatgpt.com` 与 `api.openai.com` 分别比较 IP，不同则提醒，并指出是哪个域名（多半是分流规则）。不同服务商走不同节点属于正常配置，不提醒 |
| W1 | agent 是否走系统代理之外的路径 | 系统代理已开、但 agent 环境里没有代理变量、也没有检测到 TUN 时提醒：「终端里的 agent 不读系统代理」。若此时 K1 失败，则由 K1 负责冻结 |
| W2 | 登录浏览器与终端同一出口 | 按 macOS 系统代理设置（浏览器实际使用的路径）再取一次出口，与终端路径的出口比较。不一致时提醒：登录授权与使用时 IP 不同 |
| W3 | 没有暴露大陆时区 | 官方 agent 会话实际拿到的时区属于中国大陆或港澳（`Asia/Shanghai`、`Asia/Urumqi`、`Asia/Hong_Kong`、`Asia/Macau` 等）时提醒，例如时区选了「跟随系统」。时区与出口国家不一致不提醒。登录浏览器的时区单独显示（见 5.8） |
| W4 | 无 IPv6 绕过 | 本机有公网 IPv6，且能不经代理直连 IPv6 地址时提醒：部分 agent 可能经 IPv6 直连 |

**参考检查**（不影响状态，点击才访问第三方）：IP 质量（ip.net.coffee）、浏览器环境（社区检测站），均在系统浏览器中打开。面板注明：点击后，第三方站点会收到你的出口 IP。

**按服务商分别判断：** Anthropic 和 OpenAI 各自评估、各自冻结。只有 Claude 的出口出问题时，只冻结 Claude 会话，Codex 照常工作，反之亦然。用户把两家放在不同节点上属于正常配置。

Antigravity 的服务商域名（Google）没有 trace 入口，接入后按通用出口判断。Google 请求的出口以 K1 的通用出口为准，并在详情里注明这一点。待第二期接管代理后，该差异自然消失。

### 5.3 检查时机

- **Matou 启动后：** 后台完整检查一次，不阻塞窗口和卡片。
- **后台周期：** 每 60 秒轻量采样一次，只取一个服务商的 trace。发现变化时立即触发完整检查。
- **网络变化、电脑唤醒：** 立即完整检查。
- **新开官方 agent 会话：** 使用最近一次结果。不足 60 秒的结果直接用，不等待；结果过期时也先放行启动，同时后台复检，复检失败按 5.5 冻结。只有当前状态已经是「异常」时才拦截（见 5.6）。
- **手动：** 面板里的「重新检查」。

### 5.4 出口规则

- 面板「出口规则」二选一：
  - **同一国家／地区**（默认）：出口国家变化即违规。
  - **固定 IP**：出口 IP 变化即违规。
- **建立基准：** 每个服务商第一次通过 K1 的 API 出口，自动成为该服务商的基准（记录 IP 和国家）。规则模式全局共用一个。
- **IP 变化后：** 用户可在面板点「以当前出口为准」更新基准；该操作需要当前出口通过 K1。
- **持久化：** 规则和基准跨重启保留。

### 5.5 冻结

- **冻结范围：** 所有窗口里「访问官方服务」的 agent 会话，包括：
  - 使用官方账号登录的 Claude Code（未经服务商面板切到第三方服务商）
  - Codex
  - Antigravity（接入完成后）
- **不冻结的会话：** Shell 卡片、使用第三方服务商的 Claude Code 会话。
- **触发条件：** 仅在关键检查被**确认**失败时冻结（拿到了明确的大陆 IP 或违规的 IP）。检测服务超时、全部探测失败时进入「提醒」，显示「无法确认出口」，不冻结。
- **用户看到什么：**
  - 被冻结的卡片顶部出现横幅：`出口异常（检测到中国大陆 IP），已暂停。网络恢复后自动继续。`，右侧有 `[重新检查]` `[仍要继续]` 两个按钮。
  - 终端内容保持可见、可滚动、可复制，但不接受输入。
  - 同时发一条系统通知，同一次异常只通知一次。
- **自动恢复：** 冻结期间，后台每 15 秒复检一次。复检通过（关键检查全部通过）后**自动继续**本次异常冻结的所有会话，不需要用户确认（用户 2026-11-13 决定）。横幅变为 `出口已恢复，已自动继续`，3 秒后消失；冻结时发过通知的，恢复时再发一条 `出口已恢复，N 个会话已继续`。
  - 因 K2（出口规则）冻结的会话，要等出口回到符合规则的状态才会自动继续；在面板点「以当前出口为准」后立即继续。
  - 复检通过后会连续确认两次（间隔 5 秒），再自动继续，防止节点抖动时反复冻结、解冻。
- **仍要继续：** 二次确认后解冻本次异常涉及的会话，HUD 出口标签显示「已手动继续」。在出口再次变化前不会重复冻结。这条出口是为地理库误判准备的。
- **冻结的实际效果：** 进程被暂停，不会再发出新请求。冻结时如果有请求正在进行，恢复后可能超时，agent 通常会自行重试或报错，此时用户在卡片里重试即可。

### 5.6 新会话拦截

状态为「异常」时，新起的官方 agent 会话（输入 `claude` 自动升级、新建、Fork、载入会话、重启恢复、`mt create`）照常创建卡片，但进程一启动就处于冻结状态，卡片顶部显示与 5.5 相同的横幅和按钮。进程在发出任何请求之前就被暂停，出口恢复后同样自动继续。

这样做比弹窗拦截少一步操作：所有入口（包括非交互的 `mt create` 和重启恢复）行为一致，不会出现确认框堆叠。「仍要继续」与 5.5 共享同一个越过状态。

### 5.7 设置

在「网络检查」面板里加一个「出口保护」开关，默认开启。关闭后只保留出口标签和面板，不冻结、不拦截。

### 5.8 时区：东八区、非大陆

用户 2026-11-13 决定：时区不跟随出口，改用同为东八区的非大陆时区；语言保持中文不变。

- **怎么做：** 官方 agent 会话（范围同 5.5）启动时，Matou 把会话的时区设为 `Asia/Singapore`；出口在台湾时改用 `Asia/Taipei`，出口在马来西亚、菲律宾时用当地的东八区时区，与出口国家一致。语言相关的设置一律不动。系统设置、Shell 卡片、Matou 界面都不变。
- **为什么这样选：** 东八区与北京时间读数完全相同。git 提交时间、`date`、日志、「每天早上 9 点」的定时任务、agent 报的时间，都和用户的本地时间一致，没有任何副作用。新加坡、台湾都在三家服务商的服务地区内。出口在美国等其他地区时，时区与 IP 不一致，但这种组合在出差、旅居的用户里很常见，远没有大陆时区显眼。
- **何时生效：** 会话启动或恢复时。用户本机时区如果本来就不是大陆或港澳时区（例如海外用户），Matou 不改动。
- **开关：** 复用设置里现有的 Claude Code「时区」选项，新增第一项「自动（隐藏大陆时区，推荐）」，并设为默认值。用户手动选过具体时区的，按用户的选择；选「跟随系统」的，不做替换。Codex 会话没有单独的时区设置，始终按「自动」规则处理。
- **登录浏览器：** 账号登录走的是系统浏览器的隐私窗口，默认使用系统时区。实现阶段实测能否通过启动参数或环境变量让它也用新加坡时区；做不到时，面板如实显示「登录窗口仍为本机时区」，作为提醒项。

### 5.9 面板底部

- 「复制报告」：IP 只保留前两段，不包含账号信息。
- 显示上次检测时间。
- 一行说明：检测为周期采样，无法保证每条连接都使用同一出口。

## 6. 实现要点

- **探测路径必须和 agent 一致：** 探测使用与 agent 会话**完全相同的环境变量**（复用会话环境的构建逻辑），按 `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY`（含 socks5）/ `NO_PROXY` 选择路径；没有代理变量就直连，此时若开了 TUN 会被 TUN 接管。**不能使用 Electron 的网络模块**，因为它走的是系统代理，测出来的是浏览器路径，不是 agent 路径。W2 才使用系统代理路径。
- **Claude 的额外代理配置：** Claude Code 的 `settings.json` 的 `env` 里可能配置了代理变量。Claude 会话的探测路径要合并这部分配置。
- **trace 已实测（2026-11-13）：** `claude.ai`、`api.anthropic.com`、`chatgpt.com`、`api.openai.com` 的 `/cdn-cgi/trace` 均返回 `ip=` 与 `loc=`。实现时只读这两个字段，任何解析失败都按「无法确认」处理。
- **大陆判定：** 以 Cloudflare trace 的 `loc=CN` 为准，不另外内置网段库，避免随版本更新数据。
- **冻结复用现有能力：** 复用现有的 PTY 暂停能力（`PtyExecutionPauser`）。注意它同时承担输出背压，需要改为按原因计数：背压恢复不能解冻出口冻结，反之亦然。Windows 上现有暂停只停输出、不停进程，Windows 版本的冻结需要另行确认，或在 Windows 上降级为「拦新会话 + 提醒」。
- **会话豁免：** 会话是否访问官方服务，以启动时的服务商配置为准；会话中途切换服务商时随之更新。
- **时区注入：** 只在官方 agent 会话的启动环境里设置 `TZ`，不碰 `LANG` / `LC_*`。已实测（2026-11-13，本机 Claude Code）Claude Code 会把 `Intl` 解析出的本地时区写入时间解析请求（「Local timezone:」）、定时任务和 claude.ai routines，所以替换大陆时区确有作用；语言只见于语音识别的默认语言，保持不变。Node 的 `Intl` 遵守 `TZ` 变量。Codex、Antigravity 是否上报时区待实测，即使不上报，替换也无害。
- **性能：** 检测全部在后台进行，不占用渲染进程；周期采样每分钟一次小请求。

## 7. 验收

| # | 场景 | 预期 |
|---|---|---|
| 1 | 代理正常（美国节点），开 Claude、Codex 会话 | HUD 出口标签 `🇺🇸 美国 · 出口正常`；启动无任何额外等待 |
| 2 | 关掉代理后开 Claude 会话 | 60 秒内状态变「异常」，横幅出现，系统通知一次；新开的官方会话一启动即冻结并显示横幅 |
| 3 | 规则模式下把 `api.anthropic.com` 设为直连 | Anthropic 的 K1 失败，只冻结 Claude 会话，Codex 不受影响；详情指出是该域名 |
| 3b | `claude.ai` 与 `api.anthropic.com` 走不同的海外节点 | W0 提醒，不冻结 |
| 4 | 只开系统代理、不开 TUN、无环境变量 | K1 失败并冻结，同时 W1 给出「agent 不读系统代理」的修复建议 |
| 5 | 冻结中重新开启代理 | 约 20 秒内（复检加二次确认）自动继续，横幅显示「出口已恢复，已自动继续」后消失，系统通知一次；任务不丢 |
| 5b | 冻结中节点抖动（时通时断） | 不会反复冻结、解冻；只有连续两次复检通过才继续 |

## 9. 订阅账号会话（2026-11-13 用户决定：方案 B）

「订阅账号接入 Claude Code」让 Claude Code 通过本机模型路由使用 ChatGPT 或 Antigravity 订阅。这类会话的请求由路由转发给 ChatGPT 或 Google，封号风险落在这些账号上；Claude Code 写进请求内容的本地时区也会被转发过去。

- **ChatGPT 订阅会话：** 归入新的服务商类别「ChatGPT 订阅」。探测 `chatgpt.com`（API）和 `auth.openai.com`（登录），已实测这两处都返回 trace。探测走**路由实际使用的代理**：路由按登录 shell 代理 → macOS 系统代理 → 直连的顺序选择，与 agent 会话的环境变量可能不同，所以不能复用 Codex 的「OpenAI」类别。冻结、自动恢复、越过、出口规则的行为与其他类别相同。
- **Antigravity 订阅会话：** 只隐藏大陆时区，不冻结。Google 没有 trace 入口，等 Google 类别接入（第 8 节）后再加。
- **时区：** 两种订阅会话都按「官方会话」处理（自动隐藏大陆时区）。ChatGPT 订阅会话按该类别的出口国家选择东八区时区，Antigravity 订阅会话默认新加坡。
- **不打扰未使用者：** 只有配置了 ChatGPT 订阅时才探测和显示「ChatGPT 订阅」这一组；未配置时不发请求、不出现在面板、不影响整体状态。
- **修正：** 合入前，订阅会话在判定服务商时还没注入路由地址，被误判为 Anthropic 官方会话（会跟着 Anthropic 线路冻结）。本节实现后改为按订阅类型归类。
- **界面文案：** 面板分组标题 `Claude（ChatGPT 订阅）` / `Claude (ChatGPT subscription)`；HUD 标签、横幅、通知沿用现有文案。
