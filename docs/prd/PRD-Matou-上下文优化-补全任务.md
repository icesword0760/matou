# Matou「上下文优化」补全任务（PRD §3 全量落地）

> 依据：`docs/prd/PRD-Matou-上下文与缓存优化引擎.md`、2026-11-25 与 `zou172866/Antigravity-agy-dart` 的逐项对照（对照提交 a2a8e36e）、`main@a0187ddf` 现状核查。
> 本文只定义「补什么、做到什么算完成、怎么验收」，不规定具体代码写法。

## 1. 为什么要补

启动本补全任务时，**防重复读与大文件分级** 已在真实 Hook 链路上生效，覆盖重复读、超大读、120 秒二次放行和小改动返回 diff。

其余开关属于三类"半成品"：

| 开关 | 当前实际情况 |
| --- | --- |
| 总开关 / KV-Cache 监控 | 有配置和 HUD 展示，倒计时依赖宿主用量字段，取不到就不显示；桌面提醒、通知定位未接通 |
| 终端噪音剪裁 | 命令跑完、完整输出已进上下文之后，才在 PostToolUse 追加一份摘要；Antigravity / Codex 的后置回包被丢弃 |
| 内置提速工具（mt ctx） | 命令能用，但开关没接到启动提示词，AI 不知道有这个工具 |
| KV-Cache 自动保活 | 控制器和单测存在，运行时没有任何调用，打开也不发请求 |
| 会话交接 | 按钮只把摘要复制到剪贴板，不开新会话、不注入 |
| `/compact` 后重置去重 | 代码支持 PreCompact，但三个宿主都没注册该事件，实际不触发 |

**补完的定义**：每个开关打开后都有用户可感知、可验证的真实效果；关闭后彻底无效；不再存在"开关拨了但什么都没发生"的项。

## 2. 目标（用户视角的六条判定线）

1. Claude Code 首发、Antigravity 适配验证后跟进：跑一次 50 KB 的话痨测试/构建命令，AI 上下文里只增加 ≤8.8 KB（按模型实际收到的工具结果计）；错误行在预算内全部保留，溢出时保留首因、末次错误、总数与省略数，全文可按 ID 查回。Codex 暂不自动剪裁、DSH 仅观测，UI 置灰并说明原因。
2. 同一文件重复读第二次被拦；120 秒内重试自动放行；`/compact` 之后立即重读不拦。
3. 底栏用量来自真实请求；缓存倒计时在能观测到期时间的路由上精确，其余明确标为估算或未知；缓存临过期和上下文高水位都有提醒，点提醒能定位到对应卡片。
4. 会话达到高水位时，点「带摘要开新会话」可创建新卡片并带上修改文件和最近命令结果。
5. 打开「临过期提醒」后，缓存快过期时有明确提示；「自动续命」在没有可靠通道前置灰，悬停说明"当前 Agent 不支持静默续命，自动发送会进入对话并消耗额度"，不静默失效。
6. 打开「内置提速工具」后，新会话的 AI 知道自己可以用 `mt ctx`；关闭后提示词里一个字都不多。

## 3. 硬约束（沿用 PRD，不可让步）

- 零 MCP：不注册 MCP Server、不向对话塞工具定义、不改用户全局 Agent 配置。
- 零额外常驻进程：逻辑全部在 `apps/native/runtime`，CLI 复用 `mt` 二进制。
- 零缓存前缀污染：所有动态提醒只走原生 UI，绝不往模型提示词里插动态文本；唯一例外是用户主动开启的静态工具说明（4~5 行，内容固定）。
- Fail-open：Hook 决策 150ms 硬超时，任何异常立即放行。
- 全 Agent 平等开关：Claude Code / Antigravity / Codex / DSH 同一套配置；DSH 的同步拦截与保活置灰并说明原因。
- 品牌卫生：提交前 `pnpm check:identifiers`。

## 5. 关卡拆分

每关一个可独立验收的产出，顺序按"收益/风险"排序。关卡 0 先行，1、3、5、6、7 之间可并行。

### 关卡 0：宿主协议实测与适配层（调研关，不写产品代码）—— **已完成（2026-11-25）**
结论已回写第 4 节矩阵；完整证据（28 项能力、回包原文、复现命令）保存在当次临时目录，未提交仓库。与初版假设的主要差异：Codex 不支持输出替换；Antigravity 后置没有结果正文；四家都没有可靠的保活发送通道；Claude 的压缩事件顺序为 `PreCompact → SessionStart(compact) → PostCompact`。
**要回答的问题（按宿主记录"观察 / 阻断 / 改写 / 压缩完成"四种实证）：**
- Claude Code 2.1.332：`updatedInput` 改写已实测可用；重点改为验证 `PostToolUse.updatedToolOutput` 替换内置工具输出的真实行为（结构不匹配会被静默忽略），并确认 `permissionDecision: "allow"` 是否会跳过原审批提示。
- Antigravity：`decision` / `overwrite.CommandLine` 的官方载荷形状（`toolCall.name` / `toolCall.args`）与 Matou 现有扁平解析器不匹配，先修双向适配；后置回包能否带正文/替换输出；压缩信号是否存在。
- Codex 0.169.1：源码支持 `updatedInput.command` 与 PreCompact / PostCompact；Matou 的 Codex 回调丢弃 stdout，先修同步回包；确认是否支持输出替换、读文件走 Bash 时能否识别、哪些命令能安全覆盖。
- 四个宿主的读文件工具矩阵：哪些走 `Read`、哪些走 Bash，去重前置拦截对哪个工具生效。
- 保活通道：每个宿主是否存在"同一会话、用户不可见、能确认送达"的发送通道；没有的宿主只做到期提醒。
- 命令包装的安全边界：Codex `exec_command` 前置 Hook 只暴露 `command`，看不到 `tty`；Claude 的改写与审批的关系；交互式命令、管道、后台任务的识别方式。
- 超时行为：三家 Hook 超时后命令是否照常执行（Claude 1 秒宿主超时已实测照常执行）。

**产出：** 每个宿主一张能力结论表 + 最小可运行 demo（跑一条命令、看到改写生效/不生效的证据）。
**验收：** 每个结论附命令、回包原文和宿主实际行为；未知项明确写"不支持"或"需降级"；Windows 侧先用拟支持的 shell 验适配器、带空格路径、Ctrl-C 和子进程清理。
**阻塞：** 本关结论同时决定关卡 1、2、4、7、8 的实现路径，未出结论前不动关卡 1 的产品代码。

### 关卡 1：终端剪裁源头化（收益最大）
**用户可见结果：** 超长测试/构建输出不再整段进入 AI 上下文；AI 看到的是"错误行 + 上下文 + 摘要 + 本地日志 ID"，回复更快、更少跑偏。完整原文可在本地查回。
**做法（已定方向，具体实现由执行者定）：**
- **首选路径：在模型拿到结果之前替换工具输出。** Claude Code 的 `PostToolUse.updatedToolOutput`（v2.1.121+）可以把内置工具的原始输出整体换成 ≤8.8 KB 摘要，命令本身照常执行，不需要改写用户命令，也没有重复执行风险。摘要规则、脱敏、入库复用现有 `context_guard`。
- **首发 Claude Code，第二个是 Antigravity。** Claude 走后置替换，最安全。Antigravity 走前置命令改写（agy-dart 已验证的路径）：先修载荷适配与事件标记，登录后做端到端验证，再逐类放开能确认语义的命令；不能确认的命令照常放行。
- **Codex 先修回包，命令包装暂不放开**（Hook 看不到 PTY）；DSH 保持观测。未接通的宿主在 UI 上置灰并写清是"待适配 / 待验证"还是"不支持"，`mt ctx` 仍可手动用。
- **备选路径：命令包装 `mt ctx exec -- <command>`**，只用于宿主没有输出替换能力的场景。由 `mt` 执行命令、捕获输出、剪裁入库；**必须原样保留退出码**、信号、超时语义。
- **原命令最多启动一次**：只有包装器在启动子进程之前失败（参数解析、二进制缺失等）才放行原命令；子进程一旦启动，写库失败或摘要异常只降级输出，保留原执行结果，**绝不重跑**。
- 输出替换或协议适配不成立时降级为不剪裁，UI 明确标注"该 Agent 暂不支持源头剪裁"。
- PostToolUse 追加摘要保留为兜底，但不再是主路径；兜底路径要在 UI 上区分"摘要"与"已剪裁"，且只有真正从模型结果里移除的体量才计入"已省"。
- 首版只包装/替换能确认语义的前台命令；审批、PTY、管道、后台任务、复合命令逐类验证后放开；交互式命令直接放行。

**验收标准：**
- 50 KB 输出 → 模型实际收到的工具结果 ≤8.8 KB（含宿主附加提示）；普通样本保留全部 `ERROR|FAIL|panic|assert` 行，错误密集样本保留首因、末次错误、错误总数与省略数；完整原文可按 ID 查回。
- 退出码、stdout/stderr 分流、Ctrl-C、管道、环境变量、`&&`/`;` 组合与未干预时一致；走包装路径时原命令最多执行一次（故障注入验证）。
- 包装器异常、超时、DB 锁 → 用户命令不中断；启动前的失败走原命令，启动后的失败保留原结果；`updatedToolOutput` 结构不匹配时自动退回原始输出，AI 仍能拿到完整结果。
- `/compact` 之后不重复入库同一日志；日志保留期到期后按 ID 查询给出明确失效提示。

**风险/取舍：** 用户和 AI 看到的工具输出都变成摘要（全文入库）；流式输出不再实时可见。这是 agy-dart 同样接受的取舍，需在设置项说明里写清。

### 关卡 2：压缩感知与去重重置
**用户可见结果：** `/compact` 后 AI 立刻可以重读之前读过的文件，不会"刚压缩完又被拦"。
**做法：**
- Claude Code 实测事件顺序为 `PreCompact(manual) → SessionStart(compact) → PostCompact(manual)`。`SessionStart(compact)` 已注册且现有代码会清表，但要用"压缩轮次 + 来源过滤 + 幂等"保证只重置一次；`PostCompact` 作为精确完成信号，用于重置告警和水位。
- Codex 注册 `PreCompact` / `PostCompact`，用 `PostCompact` 重置；`SessionStart(compact)` 延后到下一条正常消息，只作补充信号，避免双重清表。
- DSH 的 SDK 有 `compaction/start → summary → end`，复用现有观察桥适配，按 `compactionId` 和无 error 的 `end` 判定完成；现有桥白名单未包含这类事件。
- Antigravity 没有专用压缩事件，公开降级为"手动 `mt ctx resume` 恢复"。
- `mt ctx resume` 同时清空该会话去重表并输出修改文件和最近命令结果。
**验收：** 真实执行 `/compact` 后，重读一个大于 4 KB、低于分级上限的文件不被拦（排除 120 秒重试窗口的干扰）；分别覆盖手动压缩、自动压缩、取消压缩、压缩失败和普通恢复；无压缩时不会误清；同一轮只重置一次；`mt ctx resume` 返回内容与事实一致。

### 关卡 3：真实用量、倒计时与提醒
**用户可见结果：** 底栏显示"上下文 72k/200k、缓存剩余 3m40s"；接近水位或缓存快过期时有提醒；点提醒跳到对应卡片。
**做法：**
- 先按宿主和路由盘点可用字段：请求 ID、会话归属、真实时间、窗口、`cache_read_input_tokens` / `cache_creation_input_tokens`。能观测到期时间的路由才做精确倒计时，其余显示"估算"或"未知"，不假装精确。
- TTL 档位按模型（Claude/OpenAI/Gemini 300s、Antigravity 900s、DeepSeek 600s），用独立样本校准，不能在同一条缓存链上"一次命中后继续测过期"。
- 水位 75%/85%；缓存剩余 ≤60s 变色；桌面提醒提前 60s（默认关，用户可开）；`/compact` 后水位与告警重置。
- 提醒接入现有通知中心，明确区分应用内通知与系统通知各自的交付范围；点击定位卡片。
**验收：** 可观测路由上倒计时与实际缓存存活误差 ≤15s；不可观测路由明确显示"估算/未知"；高水位与过期提醒各触发一次并成功定位；关闭开关后零提醒、零系统通知。

### 关卡 4：自动保活真实发送
**用户可见结果：** 打开开关后，离开 3 分钟回来不会触发几十万 token 的冷重算；关闭时绝不发请求。
**做法：**
- **「自动续命」四家全部置灰 + 悬停提示**：文案说明"当前版本没有可靠的静默续命通道，自动发送会进入对话并消耗额度，故暂不开放"。置灰不是删除，用户已有的选择保留，能力就绪后按宿主自动解锁。
- **「临过期提醒」作为独立可用开关**（默认关）：缓存剩余 ≤60 秒提醒一次，点击查看；不发送任何请求。
- 未来解锁自动续命的前提：同一主会话、用户不可见、能确认送达、缓存确实续期，四条全满足；保留次数上限（默认 1）、用户新消息重置、子代理与结束会话禁入。
- 竞态检测：用户提交（`UserPromptSubmit` 等）与 provider 轮次身份更新时让位给用户消息。
- 送达未知时本轮停止重试，绝不重复扣额度。
**验收：** 四家「自动续命」均置灰且悬停有原因；无隐藏自动请求；提醒开关的开/关行为正确；未来解锁时按四条前提逐项复验。

### 关卡 5：高水位会话交接
**用户可见结果：** 会话上下文达到 85% 时，卡片出现「带摘要开新会话 / 复制摘要」。新卡片带上修改文件和最近命令结果。
**做法：**
- 点击交接入口时生成脱敏摘要，现场采集 Git 工作树的改动。
- 卡片与底栏双入口；救援路径统一用「同环境新建会话」而不是 Fork（Fork 要求会话已验证可分支，DSH 不满足）；摘要作为新会话首条上下文**只投递一次**，绑定成功后切换焦点；送达未知时提示用户手动复制。
- 通知中心点击定位。
**验收：** 点「带摘要开新会话」后创建新会话，摘要只出现一次，焦点随之切换。修改文件列表与实际一致。覆盖 DSH、切走工作区、高水位、真实退出码、日志 ID、同工作树并行修改与送达未知。复制内容需脱敏。

### 关卡 6：`mt ctx` 提示词注入与命令补全
**用户可见结果：** 开启后 AI 会主动用 `mt ctx outline/search/resume`；关闭后提示词零变化。
**做法：**
- 把现有 `managed_cli_instructions` 接到启动链，随会话托管提示词注入（4~5 行，固定文本）。
- 同步接好会话身份与数据目录：启动时注入 `MATOU_DATA_ROOT` / 会话 ID，保证 `mt ctx search/index/resume` 能找到**当前卡片**的日志，不用 `default`。
- `batch-search` 支持多查询合并去重；`resume` 输出修改文件与最近校验状态（与关卡 2 合并）。目录/网页索引单列，不占六条目标的交付路径。
**验收：** 开启后新会话首条请求包含说明（抓包或日志证据），关闭后完全没有；四宿主分别验证"AI 按说明原样调用"能取到同卡片日志；首条提示词证据与实际工具调用证据分开记录；开关对已启动会话的生效时机在文档中写明；输出 ≤8.8 KB。

### 关卡 7：面板与 PRD UI 补齐
**用户可见结果：** 面板上的每一项都有对应实物，不再有"拨了没反应"或"配置存在但界面没有"的项。
**范围：**
- `.env` 等敏感文件独立勾选（warn/deny 两档，样板文件放行）。
- 800 行分级（或明确改为按字节，二选一并写进 PRD）。
- 命中率、拦截日志详情浮层（一键复制来源 ID / 打开原文）。
- 通知中心分级显示 75% 警告和 85% 严重提醒，点击可定位到卡片。
- 设置项说明文案补齐能力边界：按宿主显示"源头剪裁 / 读保护 / 保活提醒"各自可用、需适配还是不可用；`Codex` 标"暂不支持自动剪裁"，`DSH` 标"仅观测"。
- 置灰规范：不可用或未验证的子项**保持原位、置灰、悬停提示原因与后续计划**（例如"Codex 当前版本不支持替换工具输出，已记录待适配"）；不用"看起来能开但没效果"的开关，也不把整行藏起来让用户以为功能不存在。
- "已省"只统计真正从模型结果里移除的字节；后置追加摘要不增加计数。
**验收：** 配置文件的每个字段都能在面板找到入口；可用项正常可拨，不可用项置灰且有明确原因；能力矩阵与关卡 0 结论一致；与 PRD §3 逐条对照无遗漏。

### 关卡 8：全量验收
**范围：**
- 四个 Agent 的设置交互对照矩阵（开/关、异常、恢复、持久化）。
- 性能分两项测：Hook 决策内部耗时 P95 ≤150ms；Hook 往返最大时延单独记录（HTTP 读取预算 1.5s、Antigravity 回调 1s、Codex curl 2s，慢回包时命令仍须照常执行）。PTY 吞吐与无优化时差异 ≤5%；内存增量可接受。
- 失败注入：Hook 超时、排队、卡住、SQLite 锁、DB 损坏、`mt` 缺失、晚到决策、宿主协议变更。
- 重启：配置、去重快照、日志库、保活计数按要求持久化或重置。
- 省 token 测量：固定轨迹、命令、历史、模型与缓存条件，对比模型实际收到的工具结果字节和该结果的 token 增量，并另报整次请求用量；不用单次 `input_tokens` 直接下结论。

## 6. 保真与验收方法

- 省 token 用数据说话：同一命令在开关关/开下各跑一次，比较宿主 usage 的 `input_tokens` 增量；目标 ≥80% 降幅（50 KB 输入场景）。
- 交互与性能用真实录屏和日志，不只看单测；验收材料附截图/视频与命令输出。
- 每个"一致"结论必须能定位到文件:行号或运行证据；执行者只交疑点和证据，通过与否由验收人判断。
- reference 基线：功能行为以 `Antigravity-agy-dart` 的同名能力为参照（它已跑通的部分），Matou 架构不同不算差异；数值以 PRD 为准。

## 7. 需要拍板的取舍（按 PRD 或现状仍需明确）

1. **命令改写后的可见性**：AI 和用户看到的输出变成摘要，全文入库；是否接受？替代方案只对 >16 KB 的命令包装。
2. **保活消息形态**：保活会在会话里留下一条极短请求；是否接受？还是只在用户不可见的通道做（如宿主支持）。
3. **"关闭即零残留"的口径**：PRD 写"关闭后零注入、零拦截"，当前实现是 Hook 仍注册、决策放行。是改 PRD 文案（推荐）还是改实现（注销 Hook，风险高）。
4. **800 行分级**：PRD 写了行数阈值，当前只有字节阈值；保留行数还是统一按字节（推荐按字节，跨语言更稳定）。
5. **补完后的默认开关**：是否仍保持"只开观测三项"，还是把读保护设为默认开。
6. **保活降级（已定方向）**：关卡 0 证明四家都没有"不可见 + 可确认送达"的通道；「自动续命」置灰 + 悬停提示，「临过期提醒」独立可用；未来有可靠通道再按宿主解锁。

## 8. 风险与依赖

- 关卡 1 依赖关卡 0 的结论：Claude Code 改写已实测可用；Codex 协议支持但 Matou 回包丢弃，需先修；Antigravity 载荷形状与现有解析器不匹配，需先适配。任何一家适配不成立，就在 UI 上如实标注"不支持自动剪裁"，保留 `mt ctx` 主动调用。
- 命令包装是最容易伤用户的一环：原命令最多启动一次 + 白名单 + fail-open + 退出码原样 + 交互式命令放行，任何一条不达标就不合并。尤其注意 `permissionDecision: "allow"` 可能跳过原审批提示，需单独验证。
- 保活直接花用户额度：默认关、次数上限、送达未知不重试、子代理禁入，缺一不可。
- "缓存倒计时"的可信度取决于宿主/路由能否观测真实到期时间；不可观测的路由必须在 UI 上标"估算"，不能把估算当事实卖给用户。
- 读保护的可移植性：Codex 的读文件常走 Bash，现有去重只认 `Read` 系工具；跨宿主验收要按工具类型分别做。
- SQLite FTS5 在 Windows 的可用性需在关卡 0 早期验一次、关卡 8 全覆盖（项目有 Windows 物理测试机）。
- 所有新增文案与配置键走品牌卫生门禁。

## 9. 达成判定（一句话）

面板上每一个开关都能拿出一段运行证据：开了确实发生、关了确实不发生；省 token 有前后对比数字；不再有"配置存在但链路没接"的项。

## 11. 关卡 0 实测结论（2026-11-25）

28 项能力、原始回包和复现命令已取证（临时目录，未提交仓库）。关键结论：

- **Claude Code**：输出替换可用（Bash / Read，坏结构自动回退）；`updatedInput` 全量替换，`allow` 在默认审批下会跳过确认；压缩事件顺序为 `PreCompact → SessionStart(compact) → PostCompact`；Hook 超时默认放行。
- **Codex**：**不支持输出替换**；命令改写可用，但 Matou 回调丢弃 stdout、Hook 看不到 PTY；读文件走 `exec_command`，现有去重不覆盖；`PostCompact` 可用，`SessionStart(compact)` 延后到下一正常消息。
- **Antigravity**：隔离启动停在鉴权；后置事件没有结果正文，不能用"事后替换"；但前置改写（`overwrite.CommandLine`）是 agy-dart 已验证的成熟路径，Matou 需适配 `toolCall.name/args` 与事件标记，登录后端到端验证；无专用压缩事件。
- **DSH**：SDK 有压缩完成事件（`start → summary → end`），现有观察桥未接；其余仅观测。
- **保活**：四家都没有"同一主会话、用户不可见、可确认送达"的通道，普通发送会进入会话；「自动续命」置灰 + 提示，「临过期提醒」独立可用。
- **"已省"计数**：当前后置摘要也会累加，需改为只统计真正从模型结果移除的字节。

据此调整：关卡 1 首发 Claude Code，Antigravity 走前置改写排第二；关卡 2 以 `PostCompact` 为完成信号并做幂等；关卡 4 降级为提醒；关卡 7 增加按宿主的能力矩阵。
