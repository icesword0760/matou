# Claude 账户精简版与自动用量刷新

日期：2026-10-14；版本：0.2.9，本地 macOS arm64 验收包。

## 用户可见变化

- 正常列表只保留身份、默认标记、用量与操作。移除来源说明、常驻重登说明和列表底部范围说明；单账户面板随内容收缩，不保留 Mockup 对齐展示所产生的大块空白。
- 刷新在标题栏；自动刷新只转动图标，不清空卡片、不显示全页加载、不禁用添加和管理。
- 非默认账户有明确的“切换”按钮；默认账户使用蓝色标记。真正失效的账户在卡片内显示紧凑的“登录已失效 / 重新登录”。
- 手动修复入口仍保留在管理 → 编辑中，用于用户已经看到官方 CLI 重登提示但用量服务尚未确认的场景；正常列表不反复提示。
- 未取得用量显示“—”，没有假的 0% 进度条。旧数据继续显示真实获取时间；缓存命中不把时间改成现在。
- 网络失败、超时和限流保留已有数值，轻提示重试；没有数据时明确获取失败。它们不作为登录失效的判断依据。
- 添加、授权码、重新登录、应用新凭据、范围确认、手动续接等原有流程保持。

## 自动刷新时机与边界

| 时机 | 本次行为 |
| --- | --- |
| 打开面板 | 先读取账户/缓存，后台发起用量更新检查；短时间反复打开复用结果 |
| 面板打开且窗口在前台 | 每 3 分钟调度一次，全应用共用，不按窗口倍增 |
| 新增保存 / 重登保存 / 切换成功 | 操作结束后安排更新；当前没有可见面板时留待下次查看 |
| 回到前台 / 网络恢复 / 系统唤醒 | 重新检查调度；与上次尝试至少间隔 3 分钟且数据旧时补一次，合并重复事件 |
| 重置时间 | 已知重置时间后约 15 秒安排一次核实，不自行将数值归零 |
| 面板关闭 / 最小化 / 后台 / 系统休眠 | 停止新定时请求；已经开始的读取允许结束，退出 App 会取消 |
| 手动刷新 | 立即请求更新检查；合并进行中的请求，不绕过上游缓存或 Retry-After |
| 获取失败 | 保留数据；桥接故障按 6 / 12 / 24 / 30 分钟退避。上游返回的每账户限流由上游自身门禁控制 |

复用固定版本 claude-swap `list_accounts(fetch=None)`、其持久用量缓存、请求占用锁、网络限流与凭据逻辑。Matou 只安排调用和呈现结果，不另写用量请求或令牌刷新。上游普通缓存底线 180 秒；定时触发不等于每次都有新网络数据。

主进程统一刷新任务；读取与账户修改独立。用户修改/登录/切换时取消旧用量读取，等待子进程收尾后执行，避免旧结果覆盖新身份。用量读取设置 30 秒超时，不无限占用刷新状态。
