# Claude 账户切换提示、批量重启与 HUD 用量联动

版本：0.2.10。本次以用户确认的简化 Mockup 及后续 HUD 联动要求为验收基线。

## 用户能看到和完成什么

- 切换后显示紧凑说明：“已切换账户，现有会话通常会在约 30 秒内使用新账户，或者选择立即重启并接续。”末尾直接放“立即重启”，不再占用大型绿色提示区，也没有“当前会话”续接页。
- 点击“立即重启”弹一次确认：“确定重启所有 Claude 会话窗口吗？”并说明“这会造成进行中任务的中断。”取消或 Escape 仅关闭确认框，返回原面板。
- 确定后处理 Matou 内所有运行中的 Claude 会话（包括后台、脱出窗口），允许打断进行中的任务。普通 Shell、Codex 和应用外进程不在目标集合中。
- 复用原有进程重启与已保存对话恢复通路。逐会话保留原供应商、模型、权限和对话绑定，不生成消息、不自动发送“继续”，也不重启整个 Matou。无已保存绑定的启动期或存储异常会话不会冒充接续成功。
- 在原面板内显示进度与结果；部分失败分别计数，已成功的会话不因另一个失败而回退。失败需检查对应终端的既有恢复入口。再次点击立即重启仍会先确认，其范围仍为全部 Claude 会话，而非自动重试失败项。
- HUD 的 5h / Weekly 用量复用 claude-swap 的当前默认账户快照，显示对应账户名。切换后立即使用新账户自己的缓存并刷新；没有新数据时不借用旧会话的额度。
- 上下文百分比、模型、MCP、工具等继续来自当前会话。独立供应商/API Key/独立配置的会话维持其原 HUD 来源。
- 面板关闭后，只要前台 HUD 需要账户额度，三分钟刷新继续；窗口后台或无消费者时停止安排新请求。跨窗口合并，沿用 claude-swap 缓存和限流。

## reference product / 已确认 Mockup 对照矩阵

参考底层：固定版本 claude-swap。其 switch 只更新凭据，不主动结束 Claude Code；上游描述 macOS 缓存通常约 30 秒、文件凭据后续消息生效。Matou 的约 30 秒说明不是进程实际采用新账户的遥测确认。
参考：[claude-swap Tips](https://github.com/realiti4/claude-swap#tips)，以及固定依赖 `switcher._print_switch_followup`。

| 场景 | 基线 / 要求 | 实现与证据 |
| --- | --- | --- |
| 切换提示 | 完整说明与末尾小按钮，无大型成功区 | `switched-hud.png`；无自动进程重启 |
| 确认 | 确定/取消，明确所有 Claude 与任务中断 | `restart-confirm.png`；复用应用现有 ConfirmDialog，保持统一焦点与遮罩 |
| 取消 | 弹框消失，无进程动作 | Electron 核对所有 PID 和启动日志不变，按钮焦点回归 |
| 确定 | 所有 Matou Claude，普通 Shell 保持 | 两个 busy Claude 的 PID 更新、相同对话以 --resume 重开，Shell PID 不变 |
| 脱出/后台 | 同样覆盖，去重不重复重启 | 脱出窗口专项验证；运行时按 sessionId 去重选择实际进程 owner |
| 启动失败 | 原页反馈，不假报全部完成 | `restart-failed.png`；目标账户仍保持切换结果 |
| HUD 切换 | 新账户额度，不混旧账户数据 | 38/62 → 12/24，原会话 99% 不再覆盖；上下文仍为 72% |
| 刷新来源 | 同源、隐藏面板后不停止 HUD 消费 | 两个消费者共享需求；失焦停止、回前台恢复专项 |
| 无额度 / 失效 / 限流 | 等待或错误提示，保留同账户旧数据 | HUD 组件与原账户刷新回归；不显示伪造零值 |
| 独立供应商 | 维持自身信息，不借用默认账户额度 | runtime 标记默认登录范围；组件测试独立来源仍显示原 99% |
| 原有账户能力 | 添加、授权码、重登、切换范围等保留 | 原 14 项流程及 6 项用量回归 |

证据目录：`evidence/claude-accounts-hud-restart/`。截图中的账户和额度均为合成 fixture。确认框复用现有应用级模态样式，不新增 Mockup 绘制的窗口交通灯或独立窗体。

## 技术与验证边界

- 凭据与额度继续调用 claude-swap；本次不新增 OAuth / Keychain / 用量网络实现。
- HUD 只把“本机默认账户额度”与会话自身数据区分显示，不宣称在途请求已经改用新账户。
- 批量重启每次重新枚举目标，并校验 runId、Claude profile、已保存绑定、存储/恢复状态。最大并行 3 个；等待既有恢复通路的就绪确认，超时/退出计入未完成。
- 应用外 Claude、Chrome 插件、Claude 桌面 App 不受该重启按钮控制。
- 正常账户切换沿用已有切换范围与忙碌保护；本次新增的“确定重启”明确允许中断任务。
- 自动化均使用隔离数据和本地 provider fixture，不对真实用户账户执行切换或批量重启。
