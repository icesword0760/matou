# 0.2.18 发布验收

## 用户场景

- 自动恢复最近 16 条会话，未恢复卡片保留历史并提供手动恢复入口。真实 Electron 测试创建 20 条会话，确认只启动 16 条；点击旧卡片后启动第 17 条，历史和输入可用；再次启动仍为 16 条且包含刚刚使用的卡片。
- 真实 Electron 测试验证 Runtime 崩溃后前台两个终端恢复；控制命令测试通过。
- 真实 Claude CLI 使用隔离配置和本地模拟 API 验证历史名称污染后的元数据修复与两次恢复，未调用付费推理。
- macOS 反复目录授权的本机日志确认：旧版启动的长期后台服务仍归属旧应用身份，与新临时签名的同 bundle ID 应用交替触发签名要求不匹配。经用户确认结束旧服务后，观察期间该旧进程未再触发弹窗。发布改用 Developer ID；首次签名身份迁移仍可能提示授权，不能声称所有权限弹窗永不出现。

- RuntimeServer 与存储依赖边界合计 140 项通过。
- Runtime 常规测试在修正生成目录误扫后 1172 项通过、1 项跳过。
- 账号管理 TypeScript 31 项、Python 27 项通过。
- 最近会话恢复、Runtime 崩溃恢复、Host control CLI 端到端测试 3 项通过；前两项首次因未连接指定副屏而未启动，显式选择主屏后通过。
- Host control 结构操作与跨窗口导航端到端测试另 10 项通过。
- 真实 Claude 恢复专项 1 项通过。
- 最终签名安装包冒烟测试单独运行 1 项通过，覆盖 SQLite、PTY、历史回放、截断日志恢复和未来数据库版本只读保护。首次与另一组窗口测试同时运行时，只读界面的历史标记断言失败；停止其他窗口测试后，未修改代码或断言，单独重跑通过。保留首次失败记录，不能据此认定已查明失败原因。

## 发布边界

本次发布为 macOS arm64；Developer ID 签名与 Apple 公证分别检查。签名不等于公证。没有执行完整 reference product 逐界面对照或全部端到端套件，不宣称整产品视觉交互验收全部通过。本机聊天记录、原始诊断和备份均不纳入仓库或发布附件。

最终安装包通过严格深层签名检查，指定要求基于应用标识和 Developer ID 证书团队，不再绑定单次构建的 cdhash。应用和实际使用的 macOS PTY 原生模块均为 arm64。ZIP 完整性、DMG 校验和、更新清单中的 SHA512 与文件大小均验证通过；未执行 Apple 公证。
