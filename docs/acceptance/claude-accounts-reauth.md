# Claude 账户重新登录验收

日期：2026-10-14。版本：0.2.7，本地 macOS arm64 验收包。

## 用户流程

1. Claude Code 提示重新登录时，从底栏账户面板点击「重新登录当前账户」；或在管理账户中选择具体账户的「重新登录」。已被上游确认失效的账户可直接点击失效条目。
2. 独立引导页展示账户名称和脱敏邮箱，说明只更新原记录，不新增账户，不自动重启对话。
3. 打开独立隐私窗口，以原账户授权。自动返回和手动粘贴授权码都支持；错误身份被拒绝并保留原目标供重试。
4. 核对原账户，点击「保存新登录」。保留原名称、原默认账户和现有会话；此时只保存更新后的账户副本。
5. 如果修复的是默认账户，点击「应用到本机默认登录」。运行中的 Matou 任务会阻止应用，按钮在任务结束后恢复可用，仍由用户点击，不自动排队执行。应用外任务由用户确认。
6. 应用成功后，符合条件的对话显示「重启并续接当前对话」，再次说明影响，仅用户确认后重启该卡片。未选择续接时现有进程继续运行。未提供续接能力的卡片明确提示保留终端并按 Claude 提示处理。
7. 修复非默认账户只更新其副本，提供独立切换入口；当前默认账户保持不变。

「新登录已保存、尚未应用」是非敏感持久状态，退出或重启 Matou 后仍显示「继续处理」。尚未完成或尚未保存的授权流程不跨应用重启恢复。所有隐私窗口均由用户自行关闭，包括成功、失败、取消和超时。

## 实现与复用

- 继续复用未修改的 claude-swap 0.27.0b1 和官方 Claude Code `auth login`。新增部分是 UI/流程编排，不另写 OAuth、刷新令牌或钥匙串实现。
- 同一默认账户修复显式调用上游 `switch_to(..., force=True)` 的恢复入口，避免普通“已是默认账户”短路或旧凭据备份覆盖新凭据。适配器写入前核对仍是同一默认账户；默认已被外部改变时返回冲突，不写入。
- 后台编排只在新登录已保存且用户明确应用时启用该恢复入口；不会因识别失效或授权成功自动启用。
- 授权码依然仅通过本次 CLI 的私有 stdin 管道转交，不进入磁盘、日志、命令行参数或对外发布状态。
- 账户面板打开时每 2 秒只读取会话忙闲状态，不轮询凭据或用量服务；现有全局会话门禁防止应用与任务启动竞态。

## 验证边界

- 自动化使用隔离账户 fixture；Python 契约实际调用固定版本上游，并断言新凭据被应用、旧凭据不覆盖新副本、其它凭据字段保留。
- 不将普通网络错误推断为登录失效，不对终端任意输出作自动登录判断。终端提示时提供稳定的一步入口；账户失效标记来自上游确认状态。这不是自动拦截所有 Claude Code 登录提示。
- 已有对话的真实身份和请求结果仍以官方 CLI 为准；真实账户授权、应用及续接由用户验收。
- 本次只更新账户功能，构建隔离于主目录中尚在开发的供应商配置改动；未将该组未完成代码打包。
