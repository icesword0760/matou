# 空闲 CPU 排查与修复（2026-11-01）

## 范围

第一阶段按用户要求保留全部会话，独立排查空闲消耗。随后用户明确改为每次启动只恢复最近使用的 16 条，其余手动恢复；第二阶段同时交付该策略和独立定位的空闲线程优化。以下保留各阶段测量口径。

## 原因与修改

Runtime 入口将每次 Provider HUD 回调（状态栏定时回调以及 transcript 指标刷新）连接到 refreshSessionHud。该方法会探测 Git、更新 execution_context_git_states、重新检查配置。即使没有新任务和文件变动，每个会话仍周期性触发 Git 子进程；多个 RuntimeServer 还会重复处理同一回调。

修复将这一路改为 publishSessionHud：已有内存指标直接发布。首次身份确认、实际生命周期 hook、目录变化、Git 操作、配置/Git 文件监听和显式刷新保留原刷新路径。

## 修复前实测

- 第一轮约 10 秒非连续进程快照捕捉 136 个 Runtime 子进程，其中 133 个 git status；9 个执行环境的持久 Git 检查时间改变。
- 第二轮 18.63 秒捕捉到 192 个 Git 子进程；261 个驻留进程 CPU 时间差合计约单核 37.20%，其中 Helper 合计 14.76%、Claude 合计 21.90%、Renderer 0.48%。瞬时退出子进程 CPU 不在差值汇总内；这是下界，不能当作全进程树总量。
- 测量方法：约每 180ms 读取进程树，以首末累计 CPU 时间差计算平均 CPU，Git 数是采样中出现的不同 PID 数，并非精确 exec 次数。

- 在 macOS Claude 子进程设置 MIMALLOC_PURGE_HOLES_MIN_INTERVAL=1000，将空闲内存清扫最短间隔从上游默认 100ms 放宽到 1 秒；显式大小写用户覆盖均保留。Shell/Codex 不应用该设置，不暂停任务，不关闭内存回收。

- 子进程包括 58 套 shadcn（npm 包装进程 + Node 服务）、68 个 ida-pro-mcp 和 12 个 GitNexus。用户本地前两项配置为 stdio；共用配置不意味着共用服务进程。HTTP 类型可连接共享服务，本次没有更改 MCP 连接架构。
