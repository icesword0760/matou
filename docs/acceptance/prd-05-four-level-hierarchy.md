# PRD 05 四级层级管理验收记录

状态：已通过产品验收
日期：2026-08-25
验收对象：Workspace → 事项 → 页签 → 终端

## 1. 用户获得的完整能力

### 1.1 首次进入与现场恢复

- 首次启动会在 `matou_workspace` 建立「默认事项 → 默认页签 → Shell 终端」完整现场；
- 每个工作区分别记住上次打开的事项，每个事项分别记住页签，每个页签分别记住活跃终端；
- 窗口关闭走隐藏到托盘，现场与终端进程继续保留；
- 工作区目录暂时消失时，历史层级和终端画面仍在，界面明确显示「路径失效 / 工作区目录不可用」，目录恢复后自动解除限制。

### 1.2 事项、页签与终端组织

- 事项支持新建、重命名、排序、删除；新建名称按 `新事项 / 新事项 2 / …` 递增；
- 页签支持新建、激活、溢出选择、键盘排序、关闭，以及水平/垂直分屏；
- 每个分屏拥有独立 Session 与 xterm，Shell、Claude Code、Codex 可混合存在；
- 非活跃页签的终端仍保持挂载和运行，切换页签不会重启进程；
- Renderer 仅做可重建投影，终端销毁只发生在用户明确删除并且 Runtime 事务提交之后。

### 1.3 三类破坏性入口

| 用户入口 | 用户看到的保护 | 最终影响 |
|---|---|---|
| 侧边栏事项菜单「删除」 | reference product 同款单次「提示」，明确终端会话丢失但本地目录保留 | 删除事项内全部页签与终端；需要时自动补建「默认」事项 |
| 页签「关闭」 | 非末页签静默关闭；最后事项的最后页签只显示引导提示 | 最后工作现场保持不变，引导从左侧事项菜单删除 |
| 会话「移除节点…」 | 叶节点走最短确认；有后代时必须选择仅当前节点或当前及全部后代，并展示各范围的会话与可判断的自有 Worktree 数 | 仅当前节点时后代重连祖父；完整分支时移除整棵子树；两种范围均保留文件和 Worktree |

三个入口使用独立文案和独立状态判断；会话卡片右键、停止卡片、启动/Fork 失败卡片及关闭快捷键统一进入同一个节点移除范围合同。

### 1.4 独立窗口与多窗口

- 终端通过拖拽面板头部离开窗口进入独立窗口，主窗口原位置显示「已脱出」；
- 独立窗口与主窗口使用同一 Session、PID、Journal 和 ProviderBinding；
- 关闭独立窗口会把同一终端归还原页签；原层级已归档时转入当前主窗口活跃页签；
- 应用重启不重新打开临时独立窗口，挂载状态归一为主窗口内显示；
- 脚本化控制支持把整个事项迁移到另一主窗口，Workspace 归属和所有终端进程保持不变，目标确认前失败会回滚源窗口。

## 2. 与 reference product 现有行为的对齐

> PRD 05 已完成可运行产品、代码逻辑、UI 样式和完整交互行为的逐项对照；最终结论记录于 `docs/parity/prd-05-reference-parity.md`。

- 保留工作区路径失效时「保留历史、禁止新执行、原路径恢复后继续」的用户心智；
- 保留 provider session 身份与终端进程恢复能力；
- 删除与关闭动作继续区分「本地目录」和「应用内终端现场」；
- 把 reference product 的单层工作台快照升级为 Runtime 权威的四级层级、窗口级焦点和 Scene 布局；Renderer 不再导出完整权威对象快照。

## 3. 自动化验收证据

### 3.1 组件与 Runtime

- Desktop：导航恢复、重名校验、跨工作区拖拽拒绝、页签溢出、分屏、三类确认、非活跃终端挂载、独立窗口占位；
- Runtime：默认层级原子创建、路径保护、事项/页签/终端级联、布局 CAS、PTY 提交后清理、独立窗口归还、重启归一、多窗口迁移提交与回滚；
- Contracts/Domain：协议方法、布局树、层级实体和领域事件兼容。

### 3.2 Electron 用户场景

`pnpm test:e2e` 覆盖：

1. 首次启动四级层级完整呈现；
2. 选择目录新建工作区、立即切入默认层级、实际 Shell cwd 正确；
3. 移出工作区的取消/确认、磁盘目录保留、默认工作区不回生；
4. 新建/重命名事项、新建页签、分屏、按两种范围移除会话节点，以及切换后的键盘焦点；
5. 事项顺序、Scene 分割线比例、四级现场跨应用重启恢复；
6. 非末页签关闭、最后现场保护提示、事项侧栏单次删除提示；
7. 路径失效、执行入口禁用、现场保留和原路径恢复；
8. 独立窗口脱出/归还 PID 不变，以及重启归一；
9. 整个事项跨主窗口迁移且 PID、Workspace 归属不变；
10. UtilityProcess → MessagePort → xterm 的真实 PTY 流、回放与反压链路。

`pnpm test:packaged` 覆盖安装目录产物中的 SQLite schema、node-pty、Journal 回放、Journal 尾部损坏修复和四级层级首屏。

## 4. 本期边界

- 独立窗口归还到活跃分屏右侧，不承诺恢复拖出前的精确几何槽位；
- 整个事项跨窗口迁移由脚本化控制入口提供，侧边栏暂不增加迁移菜单；
- 工作区目录失效时不提供替代目录，恢复原路径或移出工作区后再继续；
- DAG、卡片多任务、富终端标记、产物与规范检查页面属于后续 PRD。

## 5. 产品验收建议

详细的 reference product 交互对照见 `docs/parity/prd-05-reference-parity.md`。重点按真实使用顺序检查三段体验：

1. 在两个工作区、多个事项和页签间往返，确认每一级都回到离开前的位置；
2. 分别从事项、页签、会话节点三个入口触发移除，确认叶节点短路径、父节点双范围及影响数量符合预期；
3. 让一个持续输出的终端脱出、归还，再把整个事项迁移到另一窗口，确认输出连续且进程身份不变。
