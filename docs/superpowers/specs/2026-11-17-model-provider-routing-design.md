## 方案与取舍
选定页面内新增区域，最少操作即可看清混用关系；不采用独立标签页（增加切换）和组合预设卡片（超出当前需求）。复用码头既有本地请求网关和订阅适配，不引入外部服务或新代理框架。

## 用户行为
- 列表下、对话压缩上方，三行档位、供应商/账号、模型。
- 供应商只来自已经添加的 Claude Code 可接入供应商与订阅账号；不重新输入凭据。
- 默认「沿用默认供应商」，明确展示实际供应商及该档默认模型。
- 更换供应商先清空旧模型，选择合法模型后才允许保存。
- 恢复默认使三档沿用默认，仍需保存；保存成功保持焦点和滚动。
- 文案「为不同档位指定供应商和模型，未指定时沿用默认供应商。」与「使用指定供应商时，请求所需的对话内容会发送给该供应商。」
- 正式生效说明「新会话使用此分配，正在运行的会话不受影响」。保存后新启动的进程捕获配置快照；不重启、热切换现有会话。会话恢复的具体边界在实施计划中按既有生命周期明确。
- 账号失效、供应商删除、模型不可用时保留原选择并给出可操作错误；不偷偷替换目标、不自动回落到其他供应商。
- 原型演示条、假账号、假模型、模拟保存不得进入正式界面。

## 请求边界与约束
- 档位独立路由，Claude Code /model 与子代理的档位选择均适用；Opus 新别名兼容已有 Fable 行为。
- 普通请求和计数请求使用正确目标及鉴权，不能把原供应商凭据带到其他供应商。
- 对话压缩 custom 优先；follow 跟随发出该请求的实际档位，不回退旧默认供应商。
- 复用现有 GPT/订阅协议适配和 DeepSeek 工具兼容，保留流式、取消、错误传播。
- 多目标上下文/输出上限不得错误继承源供应商的能力；未知能力不夸大。订阅路由租约随会话释放。
- 老设置无新字段时行为不变；模型分配保存不能覆盖并发的压缩和上下文偏好。
- 保留已有网络出口保护，不因默认供应商是第三方而绕过实际官方目标的保护。

## 非目标
不做任意 OpenAI API 协议转换新能力、不做自动故障切换、不做组合模板、不收费、不改变应用安装和签名、不发布、不提交。正式接入以码头现有支持的供应商与订阅方式为边界。
