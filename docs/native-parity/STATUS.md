### N02a fixed implementation path and API

Port `storage/migration-runner.ts` and `storage/domain-transaction.ts` semantics directly. Generated `core/schema/migrations.json` is the complete 35-migration frozen source catalog with v2/legacy checksums; no hand-written replacement schema. `core/tests/fixtures/storage-reference.json` contains the 87 schema definitions and results actually emitted by reference source on captured Electron, including committed event rows, dedup row, replay, conflicting request and failed-mutation rollback.

Implement in `core/src/storage/{mod,migrations,transaction}.rs`, exported by `core/src/lib.rs`:

1. `configure_connection(&Connection) -> Result<()>`: existing WAL, foreign_keys ON, synchronous FULL, busy_timeout 5000, trusted_schema OFF; create only existing _runtime_meta table. Runtime generation is the future lease owner's responsibility.
2. `migrate(&mut Connection, applied_at: i64) -> Result<MigrationReport>`: ordered frozen migrations, reject newer schema/checksum mismatch, accept existing legacy checksums and update history names/checksums exactly as source. Each pending migration is an IMMEDIATE transaction. For foreignKeysOff, set OFF/legacy_alter_table ON outside transaction, verify foreign_key_check before commit, restore pragmas on success/error. Report applied versions/current version. Caller owns pre-migration backup and recovery UX, not this primitive.
3. `execute(&mut Connection, &CommandMetadata, committed_at: i64, mutation) -> Result<DomainCommit>`: source-compatible camelCase serde metadata/event/commit types; mutation receives transaction plus event vector and returns serde_json::Value. Dedup lookup first; identical request returns persisted response without invoking mutation; same ID/different hash errors. An IMMEDIATE transaction contains mutation, ordered event inserts and dedup response. Any failure rolls all three back. Preserve optional fields and defaults from source; no event bus, async framework or new retry layer.

Tests are cross-implementation contracts, not snapshots derived from the new Rust code: compare all schema objects with source fixture; compare transaction result/event/dedup fields; exercise replay without rerunning closure, request conflict, rollback, legacy/newer/corrupt migration history and close/reopen persistence. Only run this crate's tests and formatting during implementation. Root owns integrated validation and actual GUI acceptance later. Schema/transaction equality cannot be reported as native product delivery.
