# 任务：审计第二轮修复（R2-1 代码保护器）

## 目标

修复共享代码保护器：代码块内容里包含反引号时，不能把里面的反引号误当成闭合围栏，导致后续代码被清洗。

## 实际场景

system 里的代码示例可能包含字面量三反引号（例如讲 Markdown 围栏的代码），也可能有跨行的行内代码。当前保护器按“下一个相同反引号子串”找闭合，导致代码被提前结束，后面的身份句和品牌词被改写。

## 已裁决

### 围栏代码块

- 开头围栏：行首（允许前导空白）连续至少 3 个反引号，后面可以跟 info string。
- 闭合围栏：**独立一行**（允许前导和尾随空白），连续反引号数量不少于开头数量。
- 闭合前的内容全部保护，包括内容里的三反引号。
- 未闭合的围栏保护到文本末尾。

### 行内代码

- 不属于围栏开头的连续反引号 run 视为行内代码起点。
- 闭合要求相同长度的 run；允许跨行，但设置合理上限（例如 200 行），超过上限视为未闭合。
- 未闭合的行内代码不保护（保持现有保守行为）。
- 已经处于受保护区域内的反引号不再参与解析。

### 不变

- 身份句、品牌词、计费行的规则不变。
- 只改共享保护器；Antigravity 和 Codex 两条路径都受益。
- 不改变用户消息、工具、schema 的作用范围。
