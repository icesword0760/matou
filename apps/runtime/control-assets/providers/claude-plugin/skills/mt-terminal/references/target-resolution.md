# 目标与环境解析

## 固定起点

先运行 `mt identify --json`。明确稳定目标引用可直接使用；否则运行 `mt list --json`。一般目标解析仅在用户明确给出工作空间、事项、画布、标题、路径或跨窗口描述时运行 `mt list --all --json`；分支与 Worktree 环境解析始终使用全局列表。

未指定承载层级时，创建事项使用当前工作空间，创建画布使用当前事项，创建会话使用当前画布，Fork 子节点或同级节点使用当前会话。

## 当前层级相对目标

- “左边/左侧” → `left`
- “右边/右侧/隔壁” → `right`
- “同级第 N 个” → `sibling:N`
- “父会话” → `parent`
- “第 N 个子会话” → `child:N`

左右和第 N 个只在调用方当前画布的当前 DAG level 内解析。父节点、子节点、其他画布或其他窗口不会混入同级序号。

## 候选处理与导航

用户同时给出的标题、路径、profile、cwd、层级和序号都参与过滤。

- 1 个候选：参数完整时直接创建、操作或导航。
- 2–5 个候选：按 CLI 返回的详情展示标题、工作空间、事项、画布、profile、cwd 和序号，请用户选择。
- 超过 5 个候选：请用户增加一个筛选条件，不罗列长名单。

元信息仍不足时，可对少量会话候选运行 `mt read TARGET --lines 20 --json`；短读后仍有多个候选时继续请用户选择。汇报导航结果时只使用最终标题和完整路径。

## Fork 环境决策

每个 Fork 节点必须采用用户明确的环境选择：

- `{"mode":"current"}`：共享父节点当前执行环境。
- `{"mode":"existing-worktree","branch":"BRANCH","worktreeRef":"WORKTREE_REF"}`：使用列表中分支匹配的现有 Worktree。
- `{"mode":"new-worktree","branch":"BRANCH"}`：创建新分支和独立 Worktree。

普通目录只使用 `current`。不得猜测分支或 Worktree。批量方案先总结全部节点标题，再把所有缺失的环境选择集中成一个问题，避免逐项往返。

所有分支与 Worktree 环境解析统一使用 `mt list --all --json`；按 `executionContextRef`、`worktreeRef` 去重。不同会话指向相同执行环境或 Worktree 时只算一个真实候选。

父节点的 `current` 环境已承载 `main` 时使用 `current`；否则使用解析出的 `existing-worktree`；只有多个真实候选时才集中询问一次。用户说“全部在 main”或同义表达时，全部节点共享这个解析结果。

仅当至少一项环境缺失时，才把所有缺失项合并成一次询问；用户已逐项给出环境或说“全部 main”时直接解析并提交，不重复确认。内部 Worktree 引用来自 CLI JSON，不展示给用户。

## 连续指代

“它/那个/刚才那个”复用上一轮唯一且已确认的目标。“另一个/左边那个/右边那个/换成 X”会使旧目标失效，重新 list 和解析。
