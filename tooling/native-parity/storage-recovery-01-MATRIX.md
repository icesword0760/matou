# 数据库恢复交互对照矩阵

冻结口径见仓库内 `artifacts/native-parity/native/evidence/recovery-page-study-01/facts.md` 和 `plan.md`。恢复页离线输入复用 K-storage-recovery 的 `inputs.json` 和 SQLite 制备函数。两种只读工作区使用隔离的双工作空间、事项、页签与 Journal 样本。

命令与样本位置

- 子进程和断线验证位于 `apps/native/runtime/tests/process_contract/database_recovery.rs` 和 `apps/native/desktop/src/runtime_bridge.rs`。
- 隐藏探针入口为 `cargo run --manifest-path apps/native/Cargo.toml -p matou-native-desktop --example database_recovery_probe`。
- 在线归档探针入口为同包的 `archive_context_probe`。选择复制复用 K-history-selection 的原生测试环境，运行 `history_view::` 下的 6 个测试。
- 第一段冻结样本的复跑入口为 `python3 tooling/native-parity/check-database-recovery.py`。

| 场景 | 冻结证据 | 原生结果及证据 | 差异或待验 |
| --- | --- | --- | --- |
| 恢复所选备份 | F14–F18，K-storage-backup | `restore_uses_the_selected_workspace_and_preserves_evidence_on_post_replace_failure` 通过真实 Runtime 子进程验证坏 ID 拒绝且文件字节相同、.replaced 文件可读取、替换后迁移失败保留候选和 marker、从另一个有效备份进入对应工作区。备份服务合约覆盖 WAL 及发布冲突。 | 真实界面上的选择和成功切页待空闲窗口。 |
| 确认空库与保留资料 | F11、F21 | `start_empty_archives_original_files_and_rotates_seven_backups_at_normal_lifecycle_points` 验证归档目录阻塞时原位字节相同，结算被阻塞时三项归档、原隔离库和 marker 均在。同一恢复周期可复查已初始化的新库。核心测试覆盖第二次 rename 失败后第一项归档保留。 | 真实窗口焦点和视觉待空闲窗口。 |
| 恢复页导出成功和失败 | F19 | 恢复页复制当次证据和候选描述到数据根内的独立目录，返回实际路径。K 脚本核对三类原因的文件和清单、递归占用证据、目标阻塞及第二次复制拒写留下的目录。只读工作区继续走原外部目的地、原文件集合和只读清单。 | 真实窗口与文件管理器待空闲窗口。 |
| 错代际、篡改、并发 | F14–F16、F27–F29 | 现有 marker 与围栏用例核对预检查拒绝。新增真实子进程持有 SQLite 围栏时同时请求恢复、空库、导出，逐次比较文件内容；两独立 Runtime 竞争同一代际核对只有一个归档和结算。 | 仍需前台用真实窗口验收操作中退出和重连。 |
| 按阶段报告失败 | F13、F16、F18–F19 | 围栏终结、打开、结算前失败有各自阶段。核心测试在硬链接前后注入故障，以是否发布硬链接判定提交。发布后的目录同步错误记录在 Runtime 诊断，打开动作按已提交交给工作区。 | 真机断电未模拟。原位库、归档和导出目录在后段失败时可能已部分落盘。 |
| 操作选择、反馈与焦点 | F09–F12、F14、F28 | 隐藏 GPUI 探针覆盖无可用备份、选择备份、操作单飞、确认默认返回焦点、正反向 Tab 环、返回及 Escape 后复焦、错误/导出路径、旧代际确认和回包丢弃、Ready 前进度。焦点及键盘处理器由探针直接调用。 | 真实键鼠事件与前台视觉在空闲窗口验收。 |

`check-database-recovery.py` 将 K-storage-recovery 损坏库与 K-storage-backup 的已冻结备份实物配对，分别跑四项动作。备份恢复用例在 Runtime 已展示候选后改动大小、摘要、manifest 路径，另生成尺寸和摘要都匹配而完整性检查失败的 SQLite 文件，然后恢复原候选并核对哨兵记录。成功打开动作在原进程发出 Ready 后才完成请求。

七份满额隔离复现使用冻结的恢复控制器和正常退出服务，再用原生子进程核对。表中「旧」指测试中从 100 到 106 的七份有效备份，按时间从新到旧。

| 时点 | 冻结行为 | 原生处理 |
| --- | --- | --- |
| 确认前 | 旧 106、105、104、103、102、101、100 | 同一七份 |
| 新库完成迁移 | 新 pre-migration、旧 106、105、104、103、102、101 | 同样轮转掉旧 100 |
| 新库干净退出 | 新 clean-exit、新 pre-migration、旧 106、105、104、103、102 | 同样再轮转掉旧 101 |

沿用自动七份轮转，确认文案保留冻结原文。保留的旧数据归档和隔离文件各自可查。
